## Условие

Кафе на 40 посадочных мест, один зал, подсобное помещение с серверным шкафом на 6U. Есть:

- касса и POS-терминал (оплата картами);
- ноутбук администратора с доступом к товароучётной системе;
- 4 камеры видеонаблюдения с регистратором;
- гостевая сеть Wi-Fi для посетителей;
- точка подключения провайдера — один Ethernet-порт.

Требования: гости не должны видеть кассу и камеры; оплата должна работать при любом состоянии гостевой сети; записи камер хранятся 14 дней.

## Три зоны, а не одна

| Зона | Что входит | Доступ в интернет |
| --- | --- | --- |
| Касса | POS-терминал, касса, ноутбук администратора | только к платёжному провайдеру и товароучёту |
| Гости | Wi-Fi для посетителей | полный, с ограничением скорости |
| Камеры | 4 камеры и регистратор | нет |

Причина разделения не в аккуратности: гостевой Wi-Fi — самая уязвимая часть, и при общей сети компрометация точки доступа открывает путь к оплате. Камеры выводятся отдельно, потому что их трафик постоянный и не должен конкурировать с оплатой.

## Адресный план

| Сегмент | Подсеть | Шлюз | DHCP |
| --- | --- | --- | --- |
| Касса | 10.30.10.0/28 | 10.30.10.1 | нет, адреса статические |
| Гости | 10.30.20.0/24 | 10.30.20.1 | да, аренда 2 часа |
| Камеры | 10.30.30.0/28 | 10.30.30.1 | нет, статические |
| Управление | 10.30.250.0/28 | — | нет, только из шкафа |

Размер /28 на кассу (14 адресов) выбран с запасом: три устройства сейчас, место под второй терминал и принтер чеков.

## Оборудование

- Маршрутизатор с поддержкой VLAN и DHCP для гостевой сети.
- Управляемый коммутатор на 8 портов (не «мыльница»): нужны тегированные порты.
- Точка доступа Wi-Fi с отдельным SSID для гостей.
- Регистратор на 2 ТБ: 4 камеры × 14 дней при среднем качестве записи — примерно 1,2 ТБ.

## Настройка ядра

```conf
# гостям — только интернет, к локальным зонам доступа нет
nft add rule inet filter forward iifname "vlan20" oifname "wan0" accept
nft add rule inet filter forward iifname "vlan20" oifname {"vlan10","vlan30"} drop
# касса — только к платёжному адресу и товароучёту
nft add rule inet filter forward iifname "vlan10" ip daddr 203.0.113.10 accept
# камеры наружу не ходят
nft add rule inet filter forward iifname "vlan30" oifname "wan0" drop
```

Проверка правил — с конкретного устройства, а не «в целом»:

```bash
# с ноутбука в гостевой сети
ping -c 2 10.30.10.10      # должен НЕ отвечать
ping -c 2 1.1.1.1          # должен отвечать
# с кассы
ping -c 2 10.30.20.10      # должен НЕ отвечать
```

## Гостевая сеть: что ограничить

- **Скорость на клиента** — иначе один посетитель с торрентами забирает канал у кассы.
- **Аренда DHCP 2 часа** — при большом потоке посетителей адреса не заканчиваются.
- **Изоляция клиентов** (client isolation) — устройства гостей не видят друг друга.
- **Отдельный SSID без пароля**, но с порталом или хотя бы сменой пароля раз в месяц, если используется WPA2.
- **Логи не хранят MAC-адреса дольше необходимого** — это персональные данные.

## Что сдаётся

1. Схема L1: шкаф, кабели, точки, камеры.
2. Схема L2: VLAN, порты коммутатора, теги.
3. Адресный план и настройки DHCP.
4. Резервные копии конфигураций маршрутизатора и коммутатора.
5. Инструкция «что делать, если не работает оплата» на одну страницу.

## Типичные провалы

- **Одна сеть на всё.** Гость с ноутбуком видит камеры и кассу.
- **Гостевой Wi-Fi на том же коммутаторе без VLAN.** То же самое, только выглядит как «разделение».
- **Камеры пишут в облако без шифрования.** Записи уходят третьей стороне.
- **Нет резервной копии конфигурации.** Замена маршрутизатора занимает день.
- **Диск регистратора без контроля.** Запись останавливается за неделю до инцидента.

## Итог

- Зоны выделяются по требованиям: оплата, гости, наблюдение.
- Гостевая сеть не видит локальные сегменты — это проверяется, а не предполагается.
- Камеры не имеют выхода в интернет.
- Проект заканчивается схемами, адресным планом и инструкцией на случай отказа оплаты.
