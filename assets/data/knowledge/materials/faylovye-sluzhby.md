## Две независимые проверки

Когда пользователь открывает файл на общем каталоге, проверка прав происходит дважды: сначала на уровне общего ресурса (может ли он вообще подключиться), затем на уровне файловой системы (может ли он читать конкретный файл).

Итоговое право — пересечение, а не объединение. Отсюда ошибка «я дал полный доступ, а не работает»: на ресурсе выдано, в файловой системе нет. И наоборот — «в файловой системе есть, а папки не видно».

Рабочее правило: на ресурсе права широкие (`Full` для группы доступа), на файловой системе — точные. Так проще администрировать: одна точка правды.

## Структура каталогов

| Каталог | Кто пишет | Кто читает |
| --- | --- | --- |
| `common` | сотрудники | все сотрудники |
| `department` | своя группа | своя группа + руководство |
| `exchange` | все | все (обмен файлами) |
| `backup` | система | администраторы |
| `personal` | сам сотрудник | он и администратор |

Отдельный `exchange` — практичная деталь: без него сотрудники складывают обмен файлами в рабочие папки, и там появляется управляемый и неуправляемый мусор одновременно.

## Настройка в Linux (Samba)

```conf
[common]
   path = /srv/samba/common
   browseable = yes
   read only = no
   valid users = @staff
   create mask = 0660
   directory mask = 2770
   force group = staff
```

Три строки, которые чаще всего забывают:

- **`directory mask = 2770`** — старший бит `2` включает SGID: новые файлы наследуют группу каталога, а не группу создателя. Без этого через месяц половина файлов окажется недоступна коллегам.
- **`force group`** — та же задача другим способом, фиксирует группу.
- **`valid users`** — ограничение доступа явным списком, а не «всё, что было».

Проверка:

```bash
smbclient -L localhost -U operator
smbclient //localhost/common -U operator -c 'ls'
testparm -s
```

## Права: символическая запись

```text
chmod 2770 /srv/samba/common     # rwxrws--- с SGID
chgrp staff /srv/samba/common
setfacl -m g:audit:r-x /srv/samba/common   # точечное исключение для проверяющих
getfacl /srv/samba/common
```

ACL нужен там, где групповых прав не хватает: например, аудитору нужен доступ на чтение, но включать его в `staff` нельзя. `getfacl` показывает итоговые права — полезно, когда «доступ есть у всех, кроме одного».

## Квоты

Без квоты один сотрудник может заполнить том и остановить работу всех. Вариантов два:

- **Файловая система**: `xfs_quota` для XFS или `quota` для ext4.
- **Служба**: FSRM в Windows Server, модуль квот в Samba-подобных решениях.

```bash
xfs_quota -x -c 'limit -u bhard=20g operator' /srv
xfs_quota -x -c 'report -h' /srv
```

Порог предупреждения важнее жёсткого лимита: пользователь должен увидеть уведомление за гигабайт до отказа, а не в момент, когда перестало сохраняться.

## Журнал доступа

Кто удалил файл — вопрос, на который отвечает только журнал. Включают аудит объектов (Windows) или `vfs objects = full_audit` (Samba). Без журнала разбор инцидента превращается в перебор подозреваемых.

## Итог

- Права на ресурс и на файловую систему пересекаются; широкие на ресурсе, точные на ФС.
- SGID на каталогах сохраняет группу — без него права «расползаются».
- Квота с предупреждением спасает том от заполнения одним пользователем.
- Журнал доступа — единственный способ разобрать «файл пропал».
