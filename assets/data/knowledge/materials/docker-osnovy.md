## Изоляция без второго ядра

Контейнер использует ядро хоста, но изолирует процесс двумя механизмами Linux: namespaces (что процесс видит) и cgroups (сколько ресурсов он получает). Внутри контейнера своя файловая система, свой сетевой стек, свой список процессов — но ядро общее.

| | Контейнер | Виртуальная машина |
| --- | --- | --- |
| Запуск | секунды | десятки секунд |
| Размер | десятки–сотни МБ | гигабайты |
| Ядро | общее с хостом | собственное |
| Изоляция | слабее | сильнее |

Из этого следует правило безопасности: контейнер — не граница безопасности по умолчанию. Он изолирует приложение от соседей, но не защищает от ошибки в ядре. Для недоверенного кода нужна ВМ.

## Образ и слои

Образ — это слои: каждый `RUN`, `COPY`, `ADD` в Dockerfile добавляет слой. Слои кешируются, поэтому порядок инструкций определяет скорость сборки.

```dockerfile
FROM alpine:3.20
# сначала зависимости — они меняются редко
RUN apk add --no-cache nginx
# потом код — он меняется часто
COPY site/ /var/www/localhost/htdocs/
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

Ключевой приём: то, что меняется редко, ставится выше. Если сначала копировать код, а потом ставить пакеты, кеш будет сбрасываться при каждом изменении файла.

Второй приём — многоступенчатая сборка: инструменты остаются в первом образе, в финальный попадает только результат.

```dockerfile
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
```

## Данные и журналы

Файловая система контейнера исчезает при его удалении. Всё, что должно пережить пересоздание, выносится наружу.

```bash
docker run -d --name web \
  -p 8080:80 \
  -v /srv/site:/usr/share/nginx/html:ro \
  -v /srv/logs/nginx:/var/log/nginx \
  nginx:alpine
```

- **Bind mount** (`/srv/site`) — каталог хоста, удобно для конфигураций и данных, которыми управляет администратор.
- **Volume** (`docker volume create data`) — управляемое Docker хранилище, удобнее при переносе между хостами.
- **tmpfs** — только память, для временных файлов.

Журналы контейнера тоже надо ограничить, иначе диск кончится незаметно:

```json
{
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" }
}
```

## Основные команды

```bash
docker ps -a                     # все контейнеры, включая остановленные
docker logs -f web --tail 100    # журнал
docker stats                     # потребление ресурсов
docker inspect web               # полная конфигурация
docker exec -it web sh           # зайти внутрь
docker image prune -f            # убрать висячие образы
docker system df                 # сколько занимают образы, тома, кеш
```

`docker system df` стоит запускать раньше, чем «добавить диск»: часто место съедают старые образы и тома, а не данные.

## Типичные ошибки

- **Хранить данные в контейнере.** После `docker rm` их нет.
- **Копировать код перед установкой зависимостей.** Кеш не работает, сборка медленная.
- **`latest` в теге.** Неизвестно, какая версия запущена; обновление ломает неожиданно.
- **Запускать в `--privileged`.** Контейнер получает доступ к железу, изоляция исчезает.
- **Не ограничивать журналы.** Диск заполняется логами за недели.

## Итог

- Контейнер — процесс с namespaces и cgroups, ядро общее с хостом.
- Образ — слои; порядок инструкций задаёт скорость сборки.
- Данные и журналы живут вне контейнера, иначе исчезают.
- `docker system df` и `docker stats` — первые команды при «место кончилось».
