# Заметки: как устроена база знаний

Этот файл — контракт раздела заметок. Он объясняет, как добавить новую заметку,
какие поля обязательны и что из них собирается. Заметки — не статьи: это короткие
связанные записи, которые ссылаются друг на друга и на внешние источники.

## 1. Источник правды

- `assets/data/knowledge/notes.json` — все заметки: метаданные, связи, визуальные блоки, тело в Markdown.
- `assets/data/knowledge/taxonomy.json` — рубрики (зоны) и словарь тегов.
- `assets/data/knowledge/registry.json` — **генерируется**, не правится руками:
  индекс для ленты, обратные ссылки и рёбра графа.

`notes.json` собирается из `assets/data/knowledge/notes/*.md` командой
`node scripts/build-knowledge.js --collect`. Если нужен полностью автономный
источник, правьте Markdown-файлы и запускайте сборку — руками `notes.json` не
редактируется.

## 2. Поля заметки

| Поле | Обязательно | Что это |
|---|---|---|
| `id` | да | Короткий латинский идентификатор: он же имя файла и якорь ссылок |
| `title` | да | Заголовок, до 60 символов, без точки в конце |
| `zone` | да | Одна рубрика из `taxonomy.json` |
| `tags` | да | 3–7 тегов; ключи берутся из словаря `taxonomy.json` |
| `date` | да | Дата публикации, `ГГГГ-ММ-ДД` |
| `updated` | нет | Дата последней правки — выводится в шапке заметки |
| `summary` | да | Определение в 1–2 предложения: показывается под заголовком и в ленте |
| `excerpt` | да | Короткий текст для карточки в ленте, до 160 символов |
| `readtime` | да | Время чтения, например `5 мин` |
| `cover` | нет | Имя файла обложки в `assets/img/notes/` (`.webp`) |
| `related` | да | 2–4 `id` связанных заметок — из них собирается блок «Связанные» |
| `sources` | да | 2–5 внешних источников: `title`, `url`, `publisher`, `accessed` |
| `ai` | да | `true`, если текст структурирован с помощью ИИ — тогда в заметке обязательна плашка |
| `visuals` | нет | Список визуальных блоков: `table`, `terms`, `kanban`, `facts`, `figure` |
| `body` | да | Markdown-тело без заголовка первого уровня |

Внутри `body` ссылки на другие заметки пишутся как `[[id]]` или `[[id|текст ссылки]]`.
Генератор превращает их в обычные ссылки на HTML-страницы, а из них собирает
обратные ссылки и рёбра графа. Обычные markdown-ссылки остаются внешними.

## 3. Правила

1. **Машинный текст помечается всегда.** Если заметка структурирована ИИ, `ai: true`
   и в шапке выводится плашка «Текст структурирован и оптимизирован с помощью ИИ».
   Это не украшение: читатель должен понимать происхождение текста.
2. **Каждая заметка проверяема.** Минимум два источника с датой обращения и
   указанием, что именно из них взято.
3. **Связи обязательны.** Заметка без `related` не проходит сборку: именно связи
   превращают набор страниц в базу знаний.
4. **Только токены.** Никаких инлайн-стилей, литеральных цветов и `backdrop-filter`.
   Все визуальные блоки — классы `kn-*` из `assets/pages.css`.
5. **Одна рубрика.** Теги дают оттенки, рубрика — место в каталоге. Вторая рубрика
   ломает страницы рубрик и счётчики.

## 4. Сборка

```bash
node scripts/build-knowledge.js --collect   # notes.json из Markdown → страницы, рубрики, граф, лента
node scripts/build-knowledge.js             # то же без пересбора Markdown (быстро, проверка)
node scripts/build-knowledge.js --check     # только валидация контракта, без записи файлов
python3 scripts/build-search-index.py       # поисковый индекс по всем страницам
node scripts/build-post-index.js            # posts.json и счётчики лент
node scripts/build-seo.js                   # SEO-блоки, sitemap.xml, feed.xml
```

Полная пересборка контента — это пять команд подряд: сначала база знаний
(она создаёт HTML-файлы), затем индексы и SEO. В CI сборщик знаний вызывается
до `build-seo.js`, иначе новые страницы не попадут в sitemap.

Генератор пишет:

- `blog/<id>.html` — страницы заметок;
- `blog/topics.html` — указатель рубрик;
- `blog/topics/<zone>.html` — страницы рубрик;
- `blog/graph.html` — граф связей;
- `blog.html` — лента заметок (сгенерированная разметка внутри маркеров `KN:STREAM`);
- `blog/posts.json`, `feed-counts.json` — манифесты лент;
- `assets/data/knowledge/registry.json` — машинный индекс связей.

Блок между `<!-- KN:AUTO:START -->` и `<!-- KN:AUTO:END -->` в `blog.html`
перезаписывается сборкой: правки руками там запрещены.
