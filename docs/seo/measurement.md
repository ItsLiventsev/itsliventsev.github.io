# Измерения: ранжирование, индексация, поведение

Принцип: пока нет доступа к Яндекс.Вебмастеру и Google Search Console, **любая фраза
«мы выросли в поиске» — гипотеза**. Этот документ задаёт протокол, который даёт максимум
проверяемых данных без доступа и превращается в полноценный отчёт после его получения.

## 1. Что измеряем и чем

| Слой | Показатель | Источник | Статус |
| --- | --- | --- | --- |
| Индексация | число страниц в индексе, дубли, исключённые | Вебмастер «Индексирование», GSC «Страницы» | **нет доступа** |
| Покрытие | 121 индексируемая страница vs факт в индексе | `scripts/seo-audit.py` + `site:` пробы | частично доступно |
| Позиции/показы | по 20 контрольным запросам | Вебмастер «Поисковые запросы», GSC «Эффективность» | **нет доступа** |
| CTR | клики/показы по URL | там же | **нет доступа** |
| Rich results | ошибки разметки | Rich Results Test, Вебмастер | частично (ручной тест) |
| CWV | LCP/CLS/INP по URL | PageSpeed Insights (поле — по origin), `scripts/browser-lcp.js` | доступно локально |
| Поведение | визиты, дочитывания, переходы по внутренним ссылкам | Метрика | **счётчика нет** |
| AI-выдача | цитируемость в AI Overviews / Answers / Нейро | ручные пробы 2 раза в месяц | гипотеза по определению |

## 3. Поисковые операторы: что именно проверять

### Яндекс (yandex.ru, регион «Москва»)

```
site:itsliventsev.github.io                     # сколько страниц в индексе
site:itsliventsev.github.io inurl:stands        # раздел практики
site:itsliventsev.github.io inurl:assets/data    # ДУБЛИ из Markdown — должно стать 0 после T-01
site:itsliventsev.github.io inurl:docs           # ДУБЛИ документации — должно стать 0
host:itsliventsev.github.io                      # служебный оператор Яндекса: документы по хосту
"itsliventsev"                                   # бренд без оператора
title:vlan itsliventsev                          # вхождение в title
"маски, адрес сети, широковещание и VLSM"        # точная фраза (проверка уникальности)
```

### Google (google.ru, `&gl=ru&hl=ru`)

```
site:itsliventsev.github.io
site:itsliventsev.github.io -inurl:assets -inurl:docs   # «чистый» индекс
intitle:"DNS: кеш, TTL и два резолвера"
"itsliventsev" -site:itsliventsev.github.io              # упоминания извне
site:github.com ItsLiventsev itsliventsev                # внешние упоминания (ссылочный профиль)
```

Дополнительно для AI-выдачи (ручная проба, не API):
- в Google — запрос №4 и №8 без операторов, смотреть наличие AI Overview и ссылок на сайт;
- в Яндексе — «Нейро»-ответ на запрос №16 (определение SLA);
- в ChatGPT/Perplexity — те же запросы, фиксировать, цитируется ли сайт.

### Что считать результатом (а не шумом)

- `site:` даёт **все** 121 страницу и **ни одной** MD-производной — индексация чистая (T-01).
- по запросу №3–№13 сайт появляется в **топ-50** хотя бы по 3 из 10 — прогресс длинного хвоста.
- по бренду — позиция 1 и «быстрые ссылки» на разделы.

## 4. Ручной протокол без Search Console (пока доступа нет)

Частота: раз в неделю, один и тот же браузер, режим инкогнито, регион Москва
(в Яндексе — «Москва» в настройках, в Google — `&gl=ru&uule=`).

Формат записи (CSV, `docs/seo/rank-log.csv`, вести вручную или скриптом):

```csv
date,engine,region,query,top50_found,position,url_in_serp,snippet_has_faq,snippet_has_dates,notes
2026-11-04,yandex,Москва,"vlan 802.1q trunk access",no,,,no,no,"выдача — habr, docs.cisco"
2026-11-04,google,ru,"vlan 802.1q trunk access",yes,34,https://itsliventsev.github.io/blog/kn-vlan.html,no,yes,"сниппет без даты"
2026-11-04,google,ru,"site:itsliventsev.github.io inurl:assets/data",yes,,,no,no,"должно быть 0 после T-01"
```

Правила фиксации:
- `position` — только если страница реально в топ-50 на первой странице выдачи (иначе пусто);
- скриншот — при первом появлении в топ-10 и при любом изменении сниппета;
- «нет в выдаче» — тоже результат: записывать `no`, а не пропускать строку.

Ограничение метода: выдача персонализируется, ручные замеры ±5 позиций. Это сигнал
направления, а не отчёт для заказчика.

## 7. Дашборд «одним взглядом» (можно собрать из репозитория)

`scripts/seo-audit.py` уже считает то, что не требует внешних сервисов. Достаточно хранить
снимок CSV в `docs/seo/` на каждую итерацию и смотреть на 6 чисел:

1. число индексируемых маршрутов (сейчас 121);
2. страниц `inlinks=0` (сейчас 18);
3. страниц с видимым текстом < 350 слов (сейчас 59, из них 39 — «контент в JSON»);
4. title > 62 / description > 170 (42 / 48);
5. страниц с битым JSON-LD (1);
6. страниц вне sitemap без `noindex` (0 — это хорошо).

## 8. Чего не делаем

- не покупаем ссылки и не участвуем в «биржах»;
- не генерируем страницы под каждый запрос (никаких doorway);
- не ставим скрытый текст, клоакинг, накрутку поведения;
- не добавляем `aggregateRating`/`review` без реальных оценок;
- не обещаем позиции и сроки — только проверяемые изменения.
