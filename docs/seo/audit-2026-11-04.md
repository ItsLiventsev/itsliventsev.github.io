## 1. Итог одной страницей

**Хорошо (лучше, чем у 95% статических сайтов):**
canonical и OG на всех 121 индексируемых страницах; JSON-LD генерируется, а не пишется руками;
sitemap.xml и feed.xml собираются в CI и сверяются с контентом (`--check`);
`BreadcrumbList` на 114 страницах; 404 с `noindex` и живой навигацией; языковая тема без мигания;
self-hosted шрифты, критический CSS, ноль сторонних скриптов (заявленный в `docs/seo.md`
Tailwind CDN в коде **отсутствует** — документ устарел); дублей title/description нет;
битых внутренних ссылок нет; `<h1>` ровно один на каждой странице; у всех картинок есть `alt`.

**Критично (3 пункта, всё остальное — следствие):**
1. **GitHub Pages рендерит все 60 `.md` в `.html`.** `.nojekyll` в репозитории нет,
   `build_type: legacy` → Jekyll. Живьём проверено: `/AGENTS.html`, `/docs/seo.html`,
   `/assets/data/knowledge/notes/kn-dns.html` отдают HTML с темой Jekyll, без canonical,
   без description, вне sitemap. Индексируемая поверхность сайта — 181 URL вместо 121:
   **треть «страниц» сайта — случайные дубли**. В заметках при этом съедены Liquid-плейсхолдеры
   (`{{tipy}}` → пусто) и разъехались таблицы — то есть дубли ещё и битые.
2. **39 из 51 стенда не содержат текста в разметке.** Теория, задачи, тест и ситуационка лежат
   в `<script type="application/json" id="lab-data">`. Видимого текста на странице стенда в среднем
   **81 слово** (медиана по разделу). Плюс `lab-kit.js` при отсутствии профиля делает
   `location.href = 'setpolis.html?return=…'` — робот и читатель из поиска попадают не на
   лабораторную, а на хаб. Это одновременно потеря контента и риск soft-404.
3. **Нет ни одного счётчика и ни одного подтверждения владения.** 0 `yandex-verification`,
   0 `google-site-verification`, 0 Метрики/GA → измеримости нет вообще, поэтому «растёт/не растёт»
   сейчас недоказуемо. Вывод «сайт не индексируется по тематике» — **гипотеза**: проба
   `site:itsliventsev.github.io` отдаёт главную, но запрос по теме конкретной заметки страниц сайта
   не показывает; это согласуется с отсутствием подтверждения и молодостью контента, но
   без Вебмастера и GSC утверждать нельзя.

**Можно отложить:** пагинация (её нет), hreflang (не нужен), AMP/Turbo (не нужны),
переезд на свой домен, «SEO-тексты» на главную.

### 4.3 Правила перелинковки (жёсткие, проверяемые скриптом)

1. Каждая заметка ссылается минимум на **1 стенд** и **1 соседнюю заметку** (сейчас блок RELATED
   даёт стенд, соседей — 5–20 ссылок в теле: хорошо, не ломать).
2. Каждый стенд ссылается на **каталог** (без `nofollow`) и **≥ 2 заметки**.
3. Каждый хаб `/blog/topics/*` содержит таблицу «задача → заметка → стенд» на 6–12 строк.
4. Каждая заметка содержит блок «термины из этой темы» → 3–6 анкоров в `/stands/glossary.html`.
5. Каталоги вселенных содержат **статический** `<ul>` всех работ (не только JS-рендер).
6. Ни одна индексируемая страница не имеет 0 входящих внутренних ссылок (тест в CI).
7. Внутренние ссылки — без `nofollow`, кроме `admin.html` и `league.html`.
8. Хлебные крошки визуально совпадают с `BreadcrumbList` (шаблон стендов — эталон).

### Ограничения GitHub Pages, которые учтены

- **Нет серверных редиректов и заголовков.** Удаление страницы = 404; переезд = `meta refresh` +
  canonical + `noindex` (как уже сделано). Код 410 недостижим.
- **`_headers`/`.htaccess` не работают.** Кэш управляется только версионным `?v=`, что вы уже делаете.
- **Jekyll включён по умолчанию** (`build_type: legacy`) — отсюда T-01.
- **`custom_404: true`** — 404.html работает, отдаёт `noindex`; мягкие 404 (редиректы, пустые
  страницы) лечатся только контентом.
- **Trailing slash:** `/stands/` и `/stands/index.html` оба отдают 200 без редиректа → выбран
  canonical-формы `/dir/index.html`; внутренние ссылки должны быть в одной форме (сейчас так).
- **Единственный домен:** `itsliventsev.github.io` — поддомен чужого домена; для Яндекса это
  не «свой» домен, ИКС копится медленнее. Переезд на собственный домен — отдельное решение
  владельца (см. вопросы).
