# Бэклог заданий для агента-писателя

Правила серии:

- один бриф = одна страница = один интент; никаких «сборных» текстов;
- структура H2/H3 из брифа — обязательна (по ней проверяется приёмка);
- источники — реальные, с датой обращения (как в существующих 43 заметках: раздел «Источники»);
- объём — видимого текста, без учёта кода и таблиц;
- внутренние ссылки — только на существующие URL (список ниже);
- тон: инженерный, «что делать и почему», без «в современном мире» и без обещаний;
- запрещено: выдуманные цифры, «по статистике», несуществующие исследования, имя
  организации/колледжа без подтверждения, эмодзи, призывы «подпишитесь».

Общие критерии приёмки (для всех брифов):

1. `title` ≤ 60 символов, `description` 120–165, ключ в первом предложении.
2. Один `<h1>` = тема брифа; H2 — ровно по структуре; ни один H2 не пустой.
3. Абзац-определение в первом экране («X — это…», 1–2 предложения) — для AEO/цитируемости.
4. Минимум одна таблица (сравнение/параметры) и минимум один блок «что проверить/команды».
5. FAQ 3–6 вопросов, ответ 1–3 предложения, вопросы видимы на странице.
6. Блок «Источники» ≥ 2 (RFC, документация, стандарт), с датой обращения.
7. 3–6 внутренних ссылок: заметка ↔ стенд ↔ словарь.
8. Нет дублей абзацев с другими материалами (проверка: `grep` по первой строке).
9. После публикации: `node scripts/build-all.js` зелёный, `seo-audit.py` — без новых флагов.

## B-04. MTU/PMTU: почему ping идёт, а скачивание — нет

- **Тема:** фрагментация, DF, PMTU black hole.
- **Интент:** «почему не скачивается файл / не открывается сайт по https, а ping работает».
- **Кластер:** сети · `/blog/kn-mtu.html`, `/blog/kn-gre.html`, `/blog/kn-ipsec.html`.
- **Запросы:** «mtu black hole», «ping работает а сайты нет», «pmtud», «tcp mss clamping»,
  «1500 1400 mtu vpn».
- **H1:** MTU и PMTU: почему ping проходит, а большое скачивание — нет
- **Структура:** H2 «Кадр, пакет, сегмент: где появляется лимит» → H2 «Флаг DF и ICMP
  „fragmentation needed“» → H2 «Чёрная дыра PMTU: как выглядит» → H2 «Как найти рабочий MTU»
  (`ping -M do -s`) → H2 «MSS clamping в туннелях» (таблица: GRE/IPsec/PPPoE → overhead) →
  H2 «Частые вопросы».
- **Факты:** 1500 Ethernet, 24 байта GRE-заголовков (из существующей заметки), MSS = MTU − 40,
  ICMP фильтруют — PMTUD ломается.
- **FAQ:** «Почему ping -s 1472 проходит, а 1473 нет?», «Что выставить в MTU для VPN?»,
  «Помогает ли уменьшить MTU на роутере всем?».
