# Админ-панель: как добавлять посты и как устроена авторизация

Панель живёт на `/admin.html`, не индексируется (`noindex` + `robots.txt`)
и работает прямо со статического GitHub Pages — без сервера. Посты
коммитятся в репозиторий через GitHub Contents API, а индекс лент
(`posts.json`) пересобирает Action из `.github/workflows/post-index.yml`.

## Способ 1. Fine-grained PAT (по умолчанию, ничего настраивать не надо)

1. GitHub → Settings → Developer settings → **Fine-grained tokens** → Generate.
2. Repository access: **Only select repositories** → этот репозиторий.
3. Permissions → Repository permissions → **Contents: Read and write**
   (больше никаких прав не нужно).
4. Expiration: **7 или 30 дней** — никогда не создавайте токен без срока.
5. Скопируйте `github_pat_…`, откройте `/admin.html`, вставьте токен и нажмите «Войти».

### Почему это безопасно (насколько возможно на статике)

- Токен хранится только в **sessionStorage** текущей вкладки и стирается при её
  закрытии — в localStorage и в коде его нет.
- Токен ограничен одним репозиторием и одним правом (Contents).
- При любом подозрении токен отзывается в один клик в настройках GitHub —
  после этого все ранее выданные доступы мгновенно умирают.
- Минус, который надо понимать: украденный токен работает с любого устройства
  до отзыва. Поэтому короткий срок жизни и только свои устройства.

## Способ 2. GitHub Device Flow (без вставки токена)

1. GitHub → Settings → Developer settings → **OAuth Apps** → New OAuth App.
   Callback URL можно указать любой (например, URL сайта) — device flow его не использует.
2. Скопируйте **Client ID** (это публичный идентификатор, не секрет).
3. Впишите его в `assets/admin-config.js` → `oauthClientId` и закоммитьте.
4. На `/admin.html` появится вкладка «через GitHub»: панель покажет код,
   вы вводите его на `github.com/login/device`, подтверждаете доступ —
   токен выдаётся без секретов и живёт только в сессии вкладки.

Важно: OAuth App device flow выдаёт токен со скоупом `repo` (классический),
то есть шире, чем fine-grained PAT. Для одного админа PAT часто удобнее.

## Как публикуется пост

1. Выбираете раздел (блог / статьи), тип, дату, пишете заголовок и slug.
2. Текст — в облегчённом Markdown: `## заголовки`, **жирный**, *курсив*,
   `код`, списки `-`, цитаты `>`, ссылки `[текст](url)`, блоки ```` ``` ````.
3. Превью обновляется на ходу. Чекбокс «черновик» ставит
   `<meta name="post-status" content="draft">` — такая страница не попадёт в ленту.
4. «Опубликовать» создаёт коммит в ветку `main`. В течение минуты Action
   обновит `blog/posts.json` / `articles/posts.json`, и пост появится в ленте.
5. Существующие файлы видны внизу панели, их можно удалить (отдельный коммит
   с подтверждением).

## Чего панель не делает

- Не хранит паролей и не имеет серверной части — любая защита держится на
  GitHub-токене и на том, что сама страница не анонсируется.
- Не умеет загружать картинки: изображения добавляйте обычным коммитом
  в `projects/img/` или другую папку и ссылайтесь на них относительными путями.
