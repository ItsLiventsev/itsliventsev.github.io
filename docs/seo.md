# SEO: что автоматизировано и что сделать руками

Документ описывает техническую SEO-инфраструктуру сайта и ручные шаги
в Яндекс.Вебмастере, Google Search Console и Метрике. Рассчитан на
русскоязычную аудиторию и поиск Яндекса как приоритетный.

## 1. Что собирается автоматически

`scripts/build-seo.js` запускается локально и в GitHub Actions
(`.github/workflows/post-index.yml`) после каждого пуша, меняющего HTML.
Скрипт **идемпотентен**: повторный запуск заменяет SEO-блок, а не дублирует теги.

| Артефакт | Что внутри |
| --- | --- |
| SEO-блок `<!-- SEO:AUTO -->` в `<head>` 19 индексируемых страниц | canonical, полный Open Graph (включая og:image 1200×630), Twitter `summary_large_image`, JSON-LD |
| `sitemap.xml` | 19 URL, приоритеты, changefreq, lastmod из дат постов |
| `feed.xml` | RSS 2.0 по материалам `blog/posts.json` и `articles/posts.json` |
| `robots.txt` | закрыты admin-страницы, прописана директива `Sitemap` |
| `site.webmanifest` + PNG-иконки 192/512, apple-touch-icon | PWA-минимум |
| `assets/og.png` | общая OG-картинка в фирменном терминальном стиле |

JSON-LD по типам страниц:

- `WebSite` + `Person` — главная;
- `CollectionPage` — ленты (блог, статьи, проекты, архив, глоссарий);
- `Article` / `BlogPosting` — материалы (с автором, датой, keywords);
- `BreadcrumbList` — все вложенные страницы (главная → раздел → материал).

Служебные `404.html` и `admin.html` помечены `noindex` и в карту не попадают.

### Локальный запуск

```bash
node scripts/build-post-index.js   # posts.json + feed-counts.json
node scripts/build-seo.js          # sitemap, feed, SEO-блоки в head
```

При смене домена достаточно передать новый базовый URL:

```bash
SITE_URL=https://vash-domen.ru node scripts/build-seo.js
```

## 2. Ручные шаги в Яндекс.Вебмастере (webmaster.yandex.ru)

1. **Добавить сайт** `https://itsliventsev.github.io/` и подтвердить владение:
   мета-тег вставляется в `<head>` главной ВЫШЕ SEO-блока (или файл
   `yandex_*.html` в корень репозитория). После привязки своего домена
   сайт добавляется заново уже с ним.
2. **Индексирование → Файлы Sitemap**: указать
   `https://itsliventsev.github.io/sitemap.xml`.
3. **Региональность**: регион — Москва (по факту нахождения автора);
   это усиливает геозависимые запросы.
4. **Оригинальные тексты**: перед публикацией новой большой статьи
   отправлять её текст через инструмент «Оригинальные тексты» — это
   закрепляет авторство при копировании.
5. Следить за разделами **Показатели качества (Проксима/ИКС)** и
   **Диагностика**, разбирать предупреждения.
6. После переезда на свой домен использовать **Переезд сайта**.

## 3. Ручные шаги в Google Search Console (search.google.com/search-console)

1. Добавить ресурс типа «URL-префикс» `https://itsliventsev.github.io/`,
   подтвердить мета-тегом или HTML-файлом.
2. Sitemaps → отправить `sitemap.xml`.
3. Раздел «Проверка URL» → запросить индексирование главной и ключевых статей.
4. Контролировать отчёты «Индексирование страниц» и «Эффективность».

## 4. Аналитика (по желанию)

Яндекс.Метрика даёт поведенческие факторы (время на сайте, глубина, доскроллы),
которые Яндекс учитывает в ранжировании. Подключение:

1. Создать счётчик на metrika.yandex.ru, получить номер.
2. Сниппет Метрики добавляется перед `</body>` на всех страницах
   (или через GitHub Actions единым блоком). Включить опции:
   Вебвизор, точный показатель отказов, карта кликов.
3. В GSC и Вебмастере связать счётчик/ресурс между сервисами.

Без номера счётчика сниппет не добавляем — пустая Метрика вредит данным.

## 5. Контентные правила под русский поиск

- Title 30–60 символов, description 120–165: уникальные, с ключевой фразой
  в начале, без переспама (контролируется `seo-test.js`).
- Один `<h1>`, иерархия h2/h3 без пропусков уровней (тест следит за этим).
- У всех изображений — описательный русский `alt`; картинки уже `loading="lazy"`.
- ЧПУ-слаги латиницей, как сейчас: `archive/computer-networks.html`.
- Внутренняя перелинковка: ссылки между разделами (баблы навигации,
  хлебные крошки, быстрые пузыри на главной).
- `keywords` meta намеренно не используется — Яндекс и Google его игнорируют.
- hreflang не нужен: английский — это JS-переключатель на главной,
  отдельных англоязычных URL не существует.
- Турбо-страницы не используются (формат свёрнут Яндексом для обычных сайтов).

## 6. Известный технический долг

Tailwind подключён через `cdn.tailwindcss.com` на всех страницах —
это render-blocking скрипт и негативный фактор Core Web Vitals.
План: собрать Tailwind локально с purge по используемым классам и
заменить CDN на статический CSS отдельным PR с визуальной проверкой.
