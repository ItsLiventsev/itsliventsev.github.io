## 5. Активность коммитов: почему раньше не работала

Блок «Сайт собирается итерациями» показывал «100+ коммитов» и пустой график. Причин было две.

1. **График читал не то поле.** `renderChart` получал сырой ответ API и обращался к `commit.date`,
   которого в ответе GitHub нет (дата лежит в `commit.commit.committer.date`) → `Invalid Date` →
   все 14 столбцов оставались нулевыми, хотя счётчик работал.
2. **Источник данных был ненадёжным.** Прямой запрос к `api.github.com` без токена даёт 60 запросов
   в час на IP: у посетителей лента пустела, а в консоль падала сетевая ошибка. Именно из-за неё
   Lighthouse ставил главной 96 по Best Practices.

Что сделано:

- `scripts/build-activity.js` собирает снимок `assets/data/activity.json` (30 дней по дням + 60
  последних коммитов) с пагинацией, считает только содержательные коммиты — без merge и служебных
  сборок индексов;
- новый workflow `.github/workflows/activity.yml` обновляет снимок на каждый пуш в `main` и раз в
  сутки по расписанию, коммитит файл только при реальном изменении;
- `feed.js` читает снимок с того же домена (кэшируется сервис-воркером, работает офлайн), а к API
  идёт только если снимка нет; график строится из готовых счётчиков по дням;
- в интерфейсе теперь честные числа: 275 коммитов за 30 дней, последний коммит, дата, 14 столбцов
  по дням, пустые дни помечены отдельно.

Результат: блок работает и на бою, и офлайн; консольных ошибок нет; Best Practices на главной —
100. В песочнице данные те же, что отдаёт GitHub: снимок собран из `api.github.com`.

## 6. Адаптив

- Проверка `widths.js`: 15 маршрутов × 360 / 768 / 1024 / 1440 — `scrollWidth === innerWidth`
  на всех. Единственное исключение — `/admin.html` на 360 px: таблица подписчиков прокручивается
  внутри своей обёртки (`.sub-table-wrap { overflow-x: auto }`), страница при этом не едет.
- Найдено и исправлено в этой итерации: на `/projects/esports.html` при 360 px блок фактов кейса
  вылезал до 476 px. Ответственные правила вынесены в §12 `pages.css` — последний блок файла,
  который обязан перебивать слой кейсов по порядку каскада.
- Сломанный `.sr-only` (использовался в разметке, но не был объявлен) растягивал шапку на 20 px —
  утилита добавлена в `base.css`.

## 7. Регрессия контрактов (1487 утверждений)

`regression-static.js` проверяет то, что легко потерять при редизайне:

- оболочка собирается одним `shell.js`, в страницах нет дублирующей шапки и подвала;
- ассеты подключаются абсолютными путями `/assets/*.js` (иначе ломается офлайн-кэш);
- в CSS нет `backdrop-filter`, литеральных цветов вне `tokens.css`, `!important` в разметке;
- токены v13 (`--u-paper #efeee9`, `--u-surface #ffffff`, Golos в дисплее) на месте;
- текстовые правила: заголовки с заглавной, кикеры строчными, нет `//` в разметке;
- все страницы имеют `h1`, `lang="ru"`, `meta` описания, canonical, OG-теги;
- сервис-воркер версионирован (номер кэша живёт только в `sw.js`), старые кэши удаляются на `activate`;
- снимок активности: 30 дней, даты ISO, sha и url у каждого коммита, ни одного merge-коммита;
- данные каталогов, словаря и стендов соответствуют манифестам.

## 8. Справка: пустые ответы и что добавлено

Страница `/faq.html` показывала 17 вопросов с пустыми ответами: в разметке стояли
`<details><summary>…</summary><div></div></details>` — аккордеон раскрывался в пустоту.
Причина не в CSS и не в скрипте: контента в файле просто не было.

Что сделано:

- написаны все 17 ответов — по механике сайта (вселенные, формула 70/30, XP/неткоины/PRP,
  каналы сдачи, хранение прогресса, офлайн), с живыми ссылками на стенды, лигу и биржу привилегий;
- поиск по вопросам: фильтр по тексту вопроса и ответа, счётчик «найдено N вопросов»,
  пустое состояние, `Esc` очищает, `/` ставит курсор в поле;
- деплинки вида `/faq.html#faq-xp` открывают нужный ответ и подсвечивают его краем;
  ссылку можно скопировать из-под ответа одной кнопкой;
- `FAQPage`-разметка собирается из самой страницы (`scripts/build-faq-ld.py`), поэтому не
  расходится с текстом; в раздел «Не нашли ответ» вынесены живые действия;
- печать раскрывает все ответы (`beforeprint`), вёрстка для бумаги без теней;
- шапка при скролле получает волосяную линию — текст больше не «прилипает» к липкой панели.

Контракты, чтобы это не повторилось: `regression-static` проверяет, что каждый `<details>`
имеет id, вопрос и ответ длиннее 80 символов, а `FAQPage` размечен ровно для этих вопросов;
`scripts/browser-faq.js` (в CI) открывает ответ, фильтрует, переходит по деплинку, проверяет
печать и отсутствие прокрутки на 360/390/768/1440.

## 9. Ограничения проверки

- В песочнице заблокированы Google Fonts и CDN. Снимок активности уже лежит в репозитории,
  поэтому страница не зависит от внешней сети. Шрифты self-hosted.
- Headless-скриншоты логируют один `ERR_CERT_AUTHORITY_INVALID` на внешний ресурс — ожидаемо.
- `html { overflow-x: clip }` не используется: он прячет ошибки адаптива, а не решает их.
