# AGENTS.md — как вести проект itsliventsev.github.io командой агентов

Файл для людей и для агентов. Читается за 10 минут, действует на каждую задачу.
Дополняет, но не заменяет: `DESIGN_SYSTEM.md` (визуальный язык), `docs/motion.md` (движение),
`docs/seo.md` (метаданные), `QA_REPORT.md` (последние замеры).
`AGENT_PLAN.md` — исторический документ итерации v11, в работе не используется.

---

## 1. Что это за проект

Статический сайт-портфолио и учебная платформа на GitHub Pages: **140 HTML-маршрутов**
(125 контентных страниц и 15 редиректов-заглушек),
ноль рантайм-зависимостей, весь интерактив — ванильный JS, состояние — `localStorage`.

| Слой | Файлы | Объём |
|---|---|---|
| Токены | `assets/tokens.css` | 256 строк |
| Каркас и компоненты | `assets/base.css` | ~840 строк |
| Страницы и витрина | `assets/{pages,home,cases,knowledge}.css` | общий и опциональные слои |
| Стенды вселенных | `assets/course.css` | ~3 100 строк |
| Оболочка (шапка, меню, поиск, тема) | `assets/shell.js` | ~720 строк |
| Движки вселенных | `assets/{league,office-engine,ops-engine,stands,lab-kit,ops-kit,office-kit}.js` | 26 JS-файлов |
| Словарь: фильтр и тренажёр | `assets/glossary.js` | один файл на страницу `stands/glossary.html` |

**Содержание**

- `index.html` — главная (герой, лента итераций, маршруты, журнал, профиль, контакты).
- `stands/` — СетьПолис (21 страница), `stands/office/` — ОфисПолис (12), `stands/ops/` — ДатаПолис (19).
  Внутри — 15 + 10 + 16 работ, общий словарь `stands/glossary.html`, биржи привилегий, лига и трайбы.
- `projects/`, `articles/`, `blog/`, `archive/`, `faq.html`, `sitemap.html`, `admin.html`, `docs/`.

**Данные**

- `assets/data/activity.json` — снимок истории GitHub (пишется `scripts/build-activity.js`).
- `assets/search-index.json` — поисковый индекс, **собирается** из HTML: `python3 scripts/build-search-index.py`;
  в CI `--check` падает, если файл разошёлся с разметкой. Руками не правится.
- `blog/posts.json`, `articles/posts.json` — индексы публикаций; `feed-counts.json` — счётчики.
- `assets/data/topics.json` — таблица связей «заметка ↔ стенд» (мост теория ↔ практика),
  из неё `scripts/lib/related.js` собирает блоки на обеих сторонах.
- `assets/data/knowledge/` — база знаний заметок: `notes/*.md` (источник), `notes.json` (сборка),
  `taxonomy.json` (рубрики и теги), `registry.json` (рёбра связей и обратные ссылки).
  Страницы `blog/<id>.html`, `blog/topics/*.html` и лента в `blog.html` генерируются
  `scripts/build-knowledge.js` — контракт в `docs/notes.md`.
- `assets/data/knowledge/materials.json` + `materials/*.md` — учебные материалы: дерево разделов,
  групп и тем. `blog/materials.html` и `blog/materials/<id>.html` генерирует
  `scripts/build-materials.js` — контракт в `docs/materials.md`. `blog/graph.html` — заглушка-редирект,
  графа связей на сайте нет.
- `localStorage`: `stands-profile` (СетьПолис), `league-*`, `office-*`, `ops-*`. Контракты ключей менять нельзя.

## 2. Контракты, которые нельзя ломать

Это границы проекта. Нарушение = откат PR, а не спор в комментариях.

1. **URL постоянны.** 140 маршрутов и якоря на них не переименовываются. Переезд страницы — только
   заглушка с `<meta http-equiv="refresh">`, `noindex, follow` и каноническим адресом (пример: `projects/glossary.html`).
2. **SEO-блоки генерируются.** Между `<!-- SEO:AUTO:START -->` и `<!-- SEO:AUTO:END -->` правки руками
   запрещены: их перезапишут `scripts/build-seo.js` и `scripts/build-og.js`.
3. **Хранилище.** Ключи и поля `localStorage`, JSON-бандлы, коды обмена (`ITS-LAB1…`, `ITS-REV1…`) —
   обратная совместимость. Старые профили должны открываться новым кодом.
4. **Service worker меняется в одном файле.** Версию кэша и `PRECACHE` правим только в `sw.js`:
   `scripts/test-service-worker.js` выводит текущую версию и список удаляемых кешей из самого файла,
   а номер в документации фиксировать запрещено — иначе отчёты тихо отстают (так в `QA_REPORT.md`
   стоял v19 при действующем v42).
5. **Сборка идёт через `build-all`.** `build-related` вписывает блоки в готовые страницы, а
   `build-office` их перезаписывает: запусти генератор после моста — мост исчезнет (так однажды
   осталось 61 из 62 страниц). Штамп версий — последним.
6. **Общий слой не тянет лишнего.** `pages.css` грузится на всех 140 маршрутах, а слой базы знаний
   (`kn-*`) вынесен в `knowledge.css` и подключается только на 52 страницах, где есть эти классы:
   `scripts/test-css-split.js` следит за обеими сторонами (нет классов — нет файла, есть классы —
   есть файл). Для главной и кейсов выделены `home.css` и `cases.css`; тест учитывает также
   классы из подключённых скриптов. Новый опциональный слой добавляется в этот же список.
7. **Версия статики — хэш, не дата.** В шаблонах пишем путь без `?v=`, штамп добавляет его при записи
   (`scripts/lib/asset-version.js`); руками версии не правят. `build-asset-tokens.js --check` в CI ловит
   отставшую разметку, а `--write` обновляет её. Раньше токены ставили вручную и они разъехались:
   `20261104r4` у одной страницы, `20261028ab` у соседней, у CSS версии не было вовсе.
8. **Поисковый индекс только собирается.** Руками `assets/search-index.json` не правят:
   `python3 scripts/build-search-index.py` берёт h1, meta description и текст страницы (кроме
   `script`, `style`, `noscript`, `svg`, `header`, `footer`; `nav` берётся — иначе карта сайта
   выпадает из поиска). `--check` в CI падает, если файл разошёлся с разметкой; короткие страницы
   (каталоги с JS-списком) дают от 150 символов — это нижняя граница проверки, пустых записей быть
   не может. Редиректы-заглушки в индекс не попадают.
9. **Мост «теория ↔ практика» собирается, а не пишется руками.** Связи заметка ↔ стенд живут
   в `assets/data/topics.json`, блоки на страницах — между `<!-- RELATED:START -->` и
   `<!-- RELATED:END -->`. Рендер один на всех: `scripts/lib/related.js`; заметки вставляет
   `scripts/build-knowledge.js`, стенды добивает `scripts/build-related.js`. Обе стороны
   ссылаются друг на друга всегда, поэтому правка блока в HTML будет перезаписана.
10. **Каталоги на одном контракте.** «Проекты», «Статьи» и «Заметки» показывают списки одинаково:
   чипы `data-catalog-filter` (значение = тег, `all` — без фильтра), элементы `data-catalog-tags`
   (теги через пробел), контейнер `data-catalog-list`, строка состояния `data-catalog-status`,
   заглушка `data-catalog-empty`, раздел вокруг части списка `data-catalog-group` (из него фильтр
   вымел всё — раздел сворачивается вместе с заголовком). Логику держит `assets/catalog.js`;
   страница объявляет данные, а не поведение. Обработчики висят на документе: «Статьи» рисуют
   и строки, и чипы после загрузки, и привязка «к найденным узлам» уже давала мёртвые чипы в CI.
   Свой фильтр в странице или в движке — регресс, это ловит `regression-static`.
11. **Граф связей считает те же данные, что мост «теория ↔ практика».** Узлы и рёбра
   `blog/graph.html` собирает `scripts/build-knowledge.js`: связи заметок — из их `related` и
   `[[ссылок]]`, стенды — из `assets/data/topics.json` (тот же файл, что кормит блоки RELATED).
   Стенд — узел `data-kind="stand"` с квадратной точкой и подписью по наведению; на поле он
   остаётся, пока видна хотя бы одна его тема, а кнопка `data-graph-zone="stands"` показывает
   их одни. Свой список стендов или своя пара «заметка ↔ стенд» в графе — регресс: количество
   узлов-стендов сверяется с `topics.json` в `regression-static`.
12. **Кейс собирается по одному шаблону.** `article.editorial.case-study` → герой `section.esp-hero`
   с `.esp-hero-main` и `aside.case-facts` (ровно четыре `.case-fact`) → разделы `section.esp-section`
   с `.esp-label` и `h2.esp-title` → «Честный разбор» `section#verdict` из трёх `.verdict-col`
   в порядке «получилось → слабо → куда» → итоговая плашка `section.case-outcome` с `.mono.is-info`
   «итог». Безымянных `<section>` на кейсе быть не должно: раньше так и появился блок без стилей.
   Шаблон проверяет `regression-static` по обоим кейсам.
13. **Ноль зависимостей в рантайме.** jsdom, playwright, axe — только для проверок в `scripts/`.
14. **Работа без JS.** Любая навигация и контент доступны без скриптов; `shell.js` только достраивает
   шапку. `.st-*`-классы в стендах — это осознанный no-JS фолбэк, удалять их нельзя.
15. **Термины.** «Трайб» — команда, «трайн» — поток внутри трайба. Массовая замена запрещена.
16. **Порядок разделов кабинета одинаков во всех вселенных:** 01 пропуск → 02 метрики → [доска, если есть]
   → роадмап → лента → обмен кодами → как это работает. Нумерация идёт подряд без пропусков; новый раздел
   вставляется в этот порядок, а не в конец.
17. **Документация сверяется с кодом.** `DESIGN_SYSTEM.md`, `docs/design-system.md` и `docs/motion.md`
   описывают токены и тайминги словами, поэтому `regression-static` проверяет: каждый упомянутый
   `--u-*` существует в `tokens.css`, каждое число «N ms» из `docs/motion.md` есть в CSS или в
   счётных анимациях (`shell.js`, `feed.js`), а reveal объясняется через `IntersectionObserver`,
   а не через `animation-timeline`. Числа в документе — контракт, а не украшение.
18. **Карточка работы в роадмапе.** Анатомия одна: глиф маскота → заголовок → строка контекста `<p>`
   (формат работы или ОС: `.os-tag`) → полоса прогресса → справа бейдж состояния и бейдж объёма
   (часы в Офисе, формат в Сети и Дате). Бейджи не дублируют `<p>`.

## 3. Дизайн-код (коротко; полностью — `DESIGN_SYSTEM.md`)

- **Только токены** `--u-*`: цвета, кегли, отступы (4→96: `--u-s1…--u-s11`), радиусы, тени, движение.
  Хекс в компоненте — ошибка. Новый оттенок — сначала токен в `tokens.css`.
- **Один акцент** — глина. Синий / зелёный / янтарный / красный — только смысл.
- **Запрещено:** `backdrop-filter`, инлайновые `style=` (значения передаются данными: `<i data-ws-value="42">`
  → `--p` ставит `shell.js`), эмодзи-иконки, капс в русских надписях, второй акцент, градиентные заголовки.
- **`!important`** — только служебный: `[hidden]` и блоки `prefers-reduced-motion`.
- **Движение:** 120–320 мс, `--u-ease`, анимируются `transform`/`opacity`; всё под
  `@media (prefers-reduced-motion: no-preference)`, бесконечных декоративных циклов нет (кроме ленты
  итераций на главной, у неё есть кнопка «пауза»).
- **Один селектор — одно правило.** Дубли селекторов в `course.css` уже один раз вычищались: если
  нужен вариант, это отдельный класс, а не второе объявление того же селектора.
- **Текст:** заголовки — с заглавной, кикеры и метки — строчными; один `h1` на страницу.

## 4. Карта ответственности: полосы работ

Проект делится на **шесть полос**. Один агент = одна полоса = одна ветка = один PR.
Внутри полосы файлы принадлежат только ей; между полосами — через «горячие» файлы (см. §5).

| # | Полоса | Владеет файлами | Типичные задачи |
|---|---|---|---|
| **A** | Ядро и оболочка | `assets/tokens.css`, `assets/base.css`, `assets/shell.js`, `sw.js`, `scripts/test-service-worker.js`, `scripts/test-css-layers.js` | шапка и таббар, фокус, тема, движение каркаса, кеш |
| **B** | Витрина и контент | `index.html`, `assets/pages.css`, `assets/knowledge.css`, `projects.html`, `projects/`, `articles*`, `blog*`, `archive*`, `faq.html`, `sitemap.html` | главная, кейсы, публикации, справка |
| **C** | Вселенные | `stands/`, `assets/course.css`, `assets/stands.js`, `assets/league*.js`, `assets/{office,ops}-*.js`, `assets/lab-kit.js`, `assets/mascots.js`, `assets/submissions.js` | кабинеты, роадмапы, стенды, проверки |
| **D** | Данные и поиск | `assets/search-index.json`, `assets/feed.js`, `assets/home-reading.js`, `assets/data/`, `scripts/lib/site-stats.js`, `scripts/build-*.{js,py}`, `scripts/build-search-index.py` | индекс, лента активности, счётчики, числа главной |
| **E** | Качество и CI | `scripts/*` (кроме `build-*`), `.github/workflows/`, `feed.xml`, `site.webmanifest` | проверки, регрессии, axe, оффлайн |
| **F** | Документация и система | `DESIGN_SYSTEM.md`, `docs/`, `AGENTS.md`, `QA_REPORT.md`, `REFERENCES.md`, `scripts/test-design-doc.js` | описание системы, правила, отчёты |

`admin.html`, `assets/admin*.js`, `assets/admin-config.js` — полоса **C** (панель преподавателя относится к стендам).

## 5. Горячие файлы и как их делить

Четыре файла правят все, поэтому они «горячие»:

`assets/base.css` · `assets/pages.css` · `assets/course.css` · `assets/shell.js`

Правила:

1. В описании PR — строка `claims: base.css, pages.css` (перечислить горячие файлы, которые трогал агент).
2. Два агента в один момент времени не правят один и тот же горячий файл. Если очень нужно —
   второй работает **после мержа** первого, либо изменение выносится в отдельную ветку-«мост»
   (только добавления в конец файла, без пересечения строк).
3. Правки каскада обязаны сопровождаться сверкой: до/после одинаковые итоговые значения у выживших
   объявлений (см. §7, «сверка каскада»).
4. `index.html` — горячий де-факто: разметку главной правит только полоса B.

## 6. Протокол работы агента

```
1. Прочитать этот файл + DESIGN_SYSTEM.md (раздел своей полосы).
2. Получить бриф (шаблон в §9). Уточнить спорное ДО правок, а не после.
3. Ветка: arena/<id>-itsliventsev-github-io (в Arena) или fix/…, feat/… (вне Arena).
4. Правки маленькими шагами. После каждого шага — быстрые проверки (§7).
5. Коммит: conventional commits + русское описание, одна мысль на коммит.
6. PR в main: что/зачем/файлы/проверки/скриншот или замер.
7. Дождаться зелёного `verify`, только потом мерж (--merge).
```

Коммиты: `feat(ui):`, `fix(stands):`, `chore(css):`, `docs(agents):`, `test(ci):` — по-русски, в теле — что
изменилось и почему. Версии в ссылках на ассеты (`?v=…`) поднимаются при правке соответствующего файла.

### 7.2 Сверка каскада (обязательна для правок CSS-архитектуры)

Перед мержем правки, которая удаляет/переставляет правила: распарсить старый и новый файл, собрать
итоговое значение каждого свойства для каждого селектора в порядке следования и сравнить. Различия
допустимы только там, где они запланированы; всё остальное — регрессия.

### 7.3 CI

`.github/workflows/site-checks.yml`, job **`verify`** (~1.5 минуты): статические проверки → установка
браузерных зависимостей → лента/поиск/полка/каталог/оффлайн → браузерные тесты на Chromium + axe.
Красный `verify` = PR не мержится. Другие workflow: `activity.yml` (снимок истории), `post-index.yml`
(индексы публикаций).

## 11. Ловушки, на которые уже наступали

- **Node-скрипты без `NODE_PATH`** падают на `require('jsdom')`. Всегда `export NODE_PATH=/tmp/qa/node_modules`.
- **`node -e require('./assets/x.js')` — не проверка синтаксиса.** Только `node --check`.
- **jsdom не грузит относительные `link`/`script`.** Тестировать через `JSDOM.fromURL` на локальном сервере.
  «Not implemented: navigation» на страницах-редиректах — норма, `fetch is not defined` в jsdom — тоже.
- **Скрипты стендов инициализируются ~1 секунду** даже в jsdom: ждать `body.ui-ready`, а не фиксированные 300 мс.
- **head собирается один раз.** Руками написанные `<link>` и JSON-LD рядом с блоком
  `SEO:AUTO` дублируют сущности: браузер молча берёт первый, правка «одного из них» ничего не
  меняет. `scripts/test-head.js` держит ровно один экземпляр каждой.
- **Одно свойство — один слой.** Если простое правило повторяет свойство из `base.css` с другим
  значением, правка базового слоя не работает: `scripts/test-css-layers.js` это ловит.
- **Справка по оформлению — контракт, а не эссе.** Названный в `DESIGN_SYSTEM.md` класс обязан
  существовать в CSS: `scripts/test-design-doc.js` падает и на описании несуществующего компонента.
- **Числа на главной не вписывают руками.** Их считает `scripts/lib/site-stats.js`, а `scripts/test-stats.js`
  сверяет с разметкой; «41 работа» когда-то разошлась с сайтом именно потому, что жила в трёх местах.
- **axe видит промежуточный кадр.** На «живых» страницах контраст считался по анимации входа и
  ронял CI без причины: одиночный прогон заменён на повтор с паузой, разовое нарушение
  печатается как «повтор: …», постоянное остаётся. Полный отчёт — в артефакте `a11y-report.json`.
- **Лента итераций живёт в одном файле.** `assets/iter-strip.js` сам ведёт паузу, секундомер и очередь шагов;
  второй обработчик в `shell.js` давал двойное переключение `aria-pressed` — так уже было.
- **`html { overflow-x: clip }` маскирует переполнение.** Проверять ширину элементов, а не `scrollWidth`.
- **Heredoc с русским текстом в python** ломается на кавычках — использовать точные строки + `assert` на число вхождений.
- **Не «чинить» отсутствие правок из прошлых PR.** Ветка может быть срезана с более старого коммита;
  сначала `git log --oneline -3` и поиск характерных маркеров, потом выводы.
- **Инлайн-прогресс.** `style="--p:…"` в шаблонах запрещён тестом. Значение живёт в
  `<i data-ws-value="42">`, а `--p` выставляет `decorate()` из `shell.js`. Добавили новую полосу — дайте ей атрибут.
- **Системная тема.** Инлайн-скрипт в `<head>` читает `prefers-color-scheme`, если в localStorage пусто.
  Он продублирован в 75 страницах и в двух генераторах (`scripts/build-office.js`, `assets/admin.js`) —
  правится одной заменой по репозиторию, иначе `regression-static` ругнётся на отставшие страницы.
- **Поисковый индекс** собирается скриптом. Правили `<main>` — запустите `python3 scripts/build-search-index.py`,
  иначе `--check` в CI упадёт с diff-ом по url.
- **Конвейер заметок трёхшаговый:** `build-knowledge.js` (страницы + `<!-- SEO:AUTO:START/END -->`
  заглушки) → `build-seo.js` (наполняет SEO, sitemap, ленту) → `build-related.js` (стенды).
  Запуск `build-knowledge` без `build-seo` обнуляет SEO-блоки во всех 43 заметках — в diff это
  выглядит как «удалено 1300 строк», а не как ошибка генератора.
- **Кеш service worker**: после правки CSS/JS поднимать `CACHE` до `vNN+1` и править тест, иначе
  пользователи увидят старый интерфейс, а CI — расхождение.
- **Генераторы контента пишут в отслеживаемые файлы.** `scripts/build-knowledge.js` перезаписывает
  `blog.html` (блок `KN:AUTO`), `blog/*.html`, `blog/topics/`, `blog/posts.json` и `feed-counts.json`.
  Правка внутри маркеров `KN:AUTO`/`SEO:AUTO` теряется при следующей сборке: контент правится в
  Markdown-источнике `assets/data/knowledge/notes/*.md`.
- **`style=` в HTML проверяется регрессией.** Для данных, которые считает скрипт (координаты графа,
  проценты, высоты столбиков), в разметке используют `data-*`, а в CSS — переменную; инлайновый
  `style` роняет `regression-static.js`.
