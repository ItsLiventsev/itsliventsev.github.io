Введение в реляционные БД #

//текст структурирован и оптимизирован с помощью ИИ
База Данных (БД)

Упорядоченная совокупность структурированных данных.

Аналогия: библиотечный каталог или записная книжка.

СУБД

Программное обеспечение для создания и управления БД.

Аналогия: библиотекарь, который расставляет книги и ищет их по запросу (MySQL, PostgreSQL, Access).

Информационная Система

Вся система целиком: Данные + Программы + Люди + Процедуры.

Аналогия: работа библиотеки в целом, включая читателей и устав.

Реляционная база данных

Информация организована в виде взаимосвязанных таблиц (от англ. relation — отношение). Это самый распространенный тип БД.

Элемент Роль Пример
Поле (Столбец) Атрибут, определяет, что мы храним. Фамилия, Зарплата
Запись (Строка) Набор данных об одном объекте. (1, Иванов, 50000)
Первичный ключ (PK) Уникальная идентификация записи. Не может быть пустым. ID_Сотрудник, № зачетки

~ Практикум: Журнал учета приборов

Необходимо вести учет измерительных приборов и графика их поверки. Спроектируйте две связанные таблицы:

Таблица: Приборы
  • • ID_Прибора (PK, Счетчик)
  • • Наименование (Текстовый)
  • • Заводской_номер (Текстовый)
  • • Тип (Текстовый)
Таблица: Поверки
  • • ID_Поверки (PK, Счетчик)
  • • ID_Прибора (Внешний ключ)
  • • Дата_поверки (Дата/время)
  • • Следующая_поверка (Дата/время)
  • • Результат (Логический/Текст)

Вопрос для анализа: Почему ID_Прибора лучше подходит на роль первичного ключа, чем Заводской_номер? (Ответ: цифровые ID проще для ссылок, уникальны и не содержат лишних символов).
