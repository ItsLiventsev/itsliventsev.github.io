# План полной пересборки — Workspace / Learning OS

Дата: 1 ноября 2026 года. Основание: присланные LMS-референсы (контентный кабинет с левой навигацией, каталог учебных материалов, карточка курса с вкладками и боковой статистикой, дашборд прогресса/рейтинга/сертификата) и переданные HTML-примеры веб-дизайна и редакционных страниц.

## 1. Аудит репозитория и что сохраняем

Сайт — статический GitHub Pages без серверного рендеринга: 75 HTML-маршрутов, JSON-индексы контента и браузерные учебные приложения.

| Маршрут / область | Объём | Новый шаблон |
|---|---:|---|
| Главная | 1 | Workspace dashboard, Bento-панели «продолжить», быстрые разделы, опыт и навыки |
| Каталоги проектов / статей / заметок / архива | 4 | Каталог с поиском, фильтрами, компактными строками/карточками |
| Детальные проекты | 2 содержательных + redirect | Case study: хлебные крошки, основной материал, факты/связанные материалы |
| Статьи, заметки, wiki-архив | 11 содержательных + redirect | Читательский шаблон: заголовок/авторские метаданные/оглавление/контент |
| Служебные / общие | 4 | Admin, FAQ, карта сайта, 404 в общей оболочке |
| Пространства | 52 | Course dashboard, learning path, lesson workspace; существующие симуляторы и прогресс сохраняются |

Сохраняются тексты, ссылки, URL, SEO-метаданные, публикационные JSON, локальный поиск, темы, админские сценарии, сохранение профиля/прогресса, задания, проверка ответов, игровые состояния и двигатели «СетьПолис», «ОфисПолис» и «ДатаПолис». Старые визуальные стили и декоративный язык не являются источником нового интерфейса.

## 2. Информационная архитектура

- **Workspace rail** слева: обзор, обучение, проекты, статьи, заметки, база знаний, справка; активный раздел и раскрываемые группы пространств.
- **Topbar**: контекст/хлебные крошки, локальный поиск (`Ctrl/⌘K`, `/`), тема, действия пользователя.
- **Главная**: «продолжить обучение», три учебные вселенные, карточки проектов и публикаций, профиль/компетенции.
- **Каталоги**: вкладки/фильтры по разделам и аккуратная таблица/список контента; пустые, загрузочные и поисковые состояния проектируются отдельно.
- **Детальная статья/проект**: редакционная колонка + контекстный aside (оглавление, метаданные, связанные материалы); на телефоне aside переходит ниже/в раскрывающийся блок.
- **Учебное пространство**: список модулей и lessons, полосы прогресса, очки/сертификат; занятие открывается в чистом task workspace. Иконная rail не подменяет текстовые названия.

## 3. Новая дизайн-система и компоненты

Новые селекторы приложения используют префикс `ws-`, токены имеют семантические имена. Визуальный ориентир: светлая нейтральная рабочая среда, спокойные серо-лиловые поверхности и один фиолетовый акцент, белые панели, тонкие разделители, радиусы 12–20px и почти незаметные тени; пастельные статусы только для значимых состояний. Новая система не использует старую палитру как основу.

- **WorkspaceShell / Sidebar / MobileDrawer** — глобальная навигация, сворачивание на desktop, drawer и overlay на mobile.
- **Topbar / Breadcrumbs / SearchDialog** — контекст страницы и единый локальный поиск.
- **PageHeading / SurfaceCard / ActionButton / StatusTag** — заголовки, поверхности, pill-действия и семантические бейджи.
- **CourseCard / LearningPath / ProgressBar / Leaderboard / CertificatePanel** — паттерны из LMS-референсов.
- **ContentList / ArticleLayout / MetadataPanel / TableOfContents** — каталоги и чтение длинных материалов.
- Шкала 4/8/12/16/24/32px; типографика Manrope/Inter для UI, сдержанный display serif опционален только для editorial hero; видимый focus, AA-контраст, `prefers-reduced-motion`.

## 4. Технический способ миграции

Это статический проект, поэтому новая архитектура остаётся без сборочного backend-фреймворка: семантические HTML-маршруты + новая общая токенная и компонентная CSS-система + progressive-enhancement shell. Приложения практикумов остаются отдельными модулями данных/логики, но получают новый внешний Workspace-каркас. Миграция проходит шаблонами и небольшими проверяемыми группами, а не заменой учебных DOM-хуков случайными массовыми переименованиями.

## 5. Порядок реализации и критерии приёмки

1. Задокументировать аудит и компоненты (этот план), затем выпустить новые токены, оболочку и навигацию.
2. Полностью собрать главную как dashboard и проверить все исходные содержательные блоки.
3. Перенести каталоги и редакционные шаблоны, не меняя slugs и ссылки.
4. Перенести каталог обучения и все три хаба, далее применить оболочку ко всем 52 практическим маршрутам, проверяя критичные сценарии каждого движка.
5. Перенести служебные страницы, динамический шаблон публикации и собрать новые поисковые данные.
6. Запустить статическую регрессию, HTML-аудит, синтаксис JS, runtime smoke; пройти desktop/tablet/mobile на ключевых типах страниц. Не заявлять визуальную проверку/Lighthouse без фактического запуска.

Готовность: все 75 маршрутов в общей IA, никакая категория не выпадает из меню и поиска, учебные данные и пользовательские сценарии остаются рабочими, drawer/поиск доступны с клавиатуры, карточки и списки не переполняют мобильный экран, старые стили отключены в пользу новой системы.
