# Референсы и анти-паттерны

Что изучалось перед переработкой, что из этого взято и что сознательно отвергнуто.
Отдельно от `docs/vibecoding-reference.md` — там разбор приёмов vibecoding.ru, здесь — сводка решений.

---

## 1. vibecoding.ru

Источники: [главная](https://vibecoding.ru/), [сборник приёмов](https://vibecoding.ru/build/dizain-saita-bez-neiroslopa), [каталог UI-компонентов](https://vibecoding.ru/build/ui-components), [карта](https://vibecoding.ru/map).

**Взято:**
- Порядок работы: сначала референсы и «одно вау-движение», потом код. В этой итерации вау-движение одно — живая лента изменений с графиком 14 дней, а не набор эффектов.
- Готовые решения предпочтительнее самодельных: взяты проверенные паттерны (sticky-шапка + рельс оглавления, палитра поиска, каскад карточек), но реализованы на ванильном CSS/JS, потому что сайт статический и без React.
- Каталог компонентов — это каталог задач, а не анимаций: каждый компонент отвечает на вопрос «что делает пользователь».
- Выбор стиля «глазами»: тёплая бумага и глина вместо нейтрального серого SaaS.

**Не взято:** подключение React-библиотек (shadcn/ui, HeroUI, Kibo UI, Motion Primitives и др.) — избыточно для статического сайта на GitHub Pages и противоречит правилу «никаких библиотек, если хватает CSS».

## 2. DTF

Наблюдение: лента и пост живут в одном визуальном языке. У поста — крупный заголовок, узкая мера текста, плотные метаданные (дата, теги, время чтения), а лента — компактные карточки с датой слева и статусом.

**Взято:** раскладка «время слева — заголовок и теги справа» в `feed.js`; отдельная полоса метаданных у статьи; ограничение меры текста 62–68 символов; хэштеги как явные чипы, а не цветной текст.

**Не взято:** бесконечная лента с рейтингами и голосованием — на сайте нет сообщества, имитировать активность нельзя.

## 3. Т—Ж

Наблюдение: редакционная сетка, крупный Literata-подобный заголовок, спокойная палитра, плотные карточки-ссылки, аккуратные списки с номерами, подчёркивание активного пункта.

**Взято:**
- Literata как голос + Golos Text как рабочий шрифт (оба self-hosted, OFL).
- Разделительные линии вместо теней и «карточек в рамках».
- Нумерованные маршруты (`01 · Попрактиковаться`) и «01 · С чего начать» в FAQ.
- Рельс «На этой странице» справа, sticky, с подсветкой текущего раздела.

**Не взято:** «журнальная» плотность в ущерб доступности — минимальный размер интерфейсного текста 13 px, чтения — 17 px.

## 4. Прочие ориентиры

- **GOV.UK / Nielsen Norman** — правило «ссылка должна быть ссылкой»: подчёркивание в абзацах, `:focus-visible`, честные состояния ошибок.
- **WCAG 2.2** — target size 24×24 как минимум (в системе 28 px), контраст 4.5:1, `prefers-reduced-motion`.
- **GitHub Open / changelog-паттерн** — коммиты как лента: сообщение первой строкой, хэштег-классификация, относительное время, ссылка на коммит.

## 5. Анти-паттерны, которые были на сайте и удалены

| Анти-паттерн | Где было | Замена |
|---|---|---|
| Фиолетово-синий акцент `#5b4bb0` | `--u-net` (СетьПолис) | глубокий бирюзовый `#1f6467` |
| Холодный SaaS-фон `#f3f4f7` | `workspace-tokens.css` | бумага `#f6f2e9` |
| Стеклянные панели `backdrop-filter` | меню, панели стендов | плотные поверхности с линией |
| Тени-«подушки» и hover-подъём | карточки | линия + смена цвета |
| Декоративная иконка у каждого заголовка | секции главной | нумерация и моно-метки |
| Статичная «активность» с придуманными цифрами | блок «Сайт развивается итерациями» | GitHub API + честное состояние сбоя |
| Три одинаковые колонки на всех экранах | главная, словарь, кейсы | асимметричные сетки, 2 колонки в словаре |
| Дубли шапки и хлебных крошек | все страницы | одна оболочка `shell.js` |
| `!important` как способ победить каскад | 420 вхождений | слои `tokens → base → pages → course` |
| Инлайновые стили | 110 вхождений | классы + `data-*` |
| Заголовки-«строчные» в FAQ и архиве | `faq.html`, `archive.html` | «01 · С чего начать», «20 поз.» |

## 6. Что не копировалось

Тексты, изображения, брендинг и данные перечисленных сайтов не используются. Взяты только композиционные приёмы: мера текста, иерархия, способы показа метаданных и состояний.
