Бриф практики

кот Мурр — страж периметра · бриф практики

Офис получил один белый IP, а в сети — сорок машин. Знакомая задача: выпустить всех наружу через NAT и не пустить никого лишнего внутрь. Вы настроите форвардинг, трансляцию адресов и правила фильтрации на ALT, а затем сравните поведение DROP и REJECT — разницу знают только те, кто ловил таймауты в три часа ночи.

Теория

опорный конспект

01 Форвардинг и таблица nat

По умолчанию Linux не пересылает чужие пакеты. sysctl net.ipv4.ip_forward=1 делает его маршрутизатором. MASQUERADE в цепочке POSTROUTING подменяет исходный адрес на адрес внешнего интерфейса — классический офисный NAT.

# sysctl -w net.ipv4.ip_forward=1
# echo "net.ipv4.ip_forward=1" > /etc/sysctl.d/90-forward.conf
# iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
# iptables -t nat -L -n -v

02 Таблица filter: DROP против REJECT

Цепочки INPUT (себе), FORWARD (через себя), OUTPUT (от себя). DROP молча отбрасывает пакет — источник ждёт до таймаута; REJECT отвечает отказом сразу. Для внутренней сети вежливее REJECT, для внешнего периметра тише DROP.

# iptables -P FORWARD DROP
# iptables -A FORWARD -s 192.168.10.0/24 -j ACCEPT
# iptables -A FORWARD -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
# iptables -A INPUT -p tcp --dport 22 -j ACCEPT
# iptables -A INPUT -p icmp -j REJECT

03 Сохранение правил

Правила iptables живут в ядре и стираются при перезагрузке. На ALT их сохраняют в файл и восстанавливают службой (iptables-save/iptables-restore или пакет iptables-utils с юнитом). Забыть сохранить — значит повторить понедельничный инцидент.

# iptables-save > /etc/sysconfig/iptables
# systemctl enable iptables
# iptables-restore < /etc/sysconfig/iptables

Бэклог задач

чек-лист
  1. Соберите стенд: ALT-роутер (две сетевые), внутренняя сеть 192.168.10.0/24, внешний интерфейс eth0
  2. Включите ip_forward персистентно через /etc/sysctl.d и проверьте sysctl net.ipv4.ip_forward
  3. Настройте MASQUERADE для внутренней подсети, проверьте доступ с ПК на внешний ресурс (пинг/HTTP)
  4. Посмотрите таблицу трансляций conntrack/iptables -t nat -L во время соединения
  5. Установите политику FORWARD DROP и явно разрешите установленную сессию (conntrack ESTABLISHED,RELATED)
  6. Разрешите SSH только из внутренней подсети, закройте остальной INPUT, сравните DROP и REJECT на практике
  7. Заблокируйте ping (ICMP) и зафиксируйте разницу в поведении команд диагностики
  8. Сохраните правила и подтвердите их восстановление после reboot

Задача считается выполненной после реальной работы на оборудовании, в эмуляторе или на виртуальной машине. В интерактиве чек-лист сохраняет прогресс.

Ситуационная задача

Ситуационная задача. Кейс «ТехноСервис»: после смены политики firewall перестали открываться сайты по доменным именам, хотя ping до 8.8.8.8 проходит. DNS не отвечает. Найдите забытое правило (порт 53 UDP/TCP), исправьте цепочку и добавьте регрессионную проверку в чек-лист.

Проверь себя

контрольный тест
Вопрос 1. Что включает net.ipv4.ip_forward=1?
  • NAT автоматически
  • Пересылку пакетов между интерфейсами — режим маршрутизатора верно
  • Шифрование трафика
  • Службу DNS

Ответ: Пересылку пакетов между интерфейсами — режим маршрутизатора

Форвардинг — лишь разрешение транзита; NAT настраивается отдельно.

Вопрос 2. Чем DROP отличается от REJECT?
  • Ничем
  • DROP молчит, REJECT отправляет сообщение об отказе верно
  • REJECT быстрее в 10 раз
  • DROP работает только на UDP

Ответ: DROP молчит, REJECT отправляет сообщение об отказе

Источник за DROP ждёт таймаут, за REJECT сразу получает ICMP-отказ.

Вопрос 3. В какой цепочке настраивается MASQUERADE?
  • INPUT таблицы filter
  • POSTROUTING таблицы nat верно
  • OUTPUT таблицы mangle
  • FORWARD таблицы raw

Ответ: POSTROUTING таблицы nat

Исходный адрес подменяется после маршрутизации — POSTROUTING/nat.

Вопрос 4. Что произойдёт с правилами iptables после перезагрузки без сохранения?
  • Они в прошивке ядра
  • Сотрутся, загрузится пустая/дефолтная политика верно
  • Сохранятся в /tmp
  • Будут закомментированы

Ответ: Сотрутся, загрузится пустая/дефолтная политика

Правила живут в оперативной памяти ядра — нужен iptables-save и служба восстановления.

Вопрос 5. Какое состояние conntrack разрешает обратный трафик открытой сессии?
  • NEW
  • ESTABLISHED,RELATED верно
  • INVALID
  • UNTRACKED

Ответ: ESTABLISHED,RELATED

Ответные и связанные пакеты пропускают по ESTABLISHED,RELATED при DROP по умолчанию.
