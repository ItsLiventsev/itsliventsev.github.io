Бриф практики

Нельзя обслуживать то, чего нет в учёте. Смена получает задачу навести порядок: собрать инвентаризацию серверов автоматически, а не обходить стойки с блокнотом, и завести сервисный каталог — что за сервис, кто владелец, какой SLA. Здесь появляется Ansible: тот самый инструмент, которым на демоэкзамене собирают факты со всего стенда одной командой.

Теория

опорный конспект

01 Зачем автоматическая инвентаризация

Ручные таблицы устаревают в день создания. Ansible по SSH собирает факты (facts): ОС, интерфейсы, диски, память — без агента на целевых машинах. Повторный запуск показывает расхождения.

# apt-get install ansible
# mcedit inventory
[servers]
srv-hq ansible_host=10.20.30.11
# ansible all -m ping
# ansible all -m setup -a "filter=ansible_distribution*"

02 Сервисный каталог

Каталог отвечает на вопросы: какой сервис, кто владелец, на каких серверах работает, какой уровень критичности и SLA. Без каталога каждая заявка начинается с расследования, чей это сервис.

03 Документ как артефакт

Реестр и каталог оформляются таблицами и схемами — это часть базы знаний. В следующих спринтах на них будут ссылаться runbook и изменения.

⚑ Пасхалка: в СетьПолисе студенты уже документировали сеть на трёх этажах — здесь вы делаете следующий шаг, ведёте учёт во времени.

Бэклог задач

чек-лист
  1. Подготовьте ansible inventory на 2–3 сервера и добейтесь ansible all -m ping
  2. Соберите факты setup и выгрузите дистрибутивы, версии ядер и объёмы памяти
  3. Снимите инвентаризацию дисков и сетевых адаптеров по каждому узлу
  4. Составьте реестр: имя, роль, ОС, IP, расположение, ответственный
  5. Заведите сервисный каталог из 4 сервисов с владельцем, критичностью и SLA
  6. Постройте простую схему размещения сервисов по серверам
  7. Повторно прогоните сбор фактов и опишите, как ловить расхождения

Задача считается выполненной после реальной работы на оборудовании, в эмуляторе или на виртуальной машине. В интерактиве чек-лист сохраняет прогресс.

Проверь себя

контрольный тест
Вопрос 1. Зачем Ansible не требует агента на целевых машинах?
  • Он работает по SSH/WinRM верно
  • Он читает реестр удалённо через флешку
  • Агент встроен в BIOS
  • Ему нужен только браузер

Ответ: Он работает по SSH/WinRM

Ansible agentless: подключается по SSH (Linux) или WinRM (Windows).

Вопрос 2. Что относится к сервисному каталогу?
  • Только пароли
  • Сервис, владелец, критичность, SLA, серверы верно
  • Личные заметки инженера
  • Расписание отпусков

Ответ: Сервис, владелец, критичность, SLA, серверы

Каталог описывает услугу и её эксплуатационные характеристики.

Вопрос 3. Какой модуль Ansible собирает системные факты?
  • ping
  • setup верно
  • copy
  • service

Ответ: setup

setup возвращает ansible_facts: ОС, интерфейсы, диски и т.д.

Вопрос 4. Главный недостаток ручного реестра в Excel?
  • Его нельзя открыть
  • Быстро устаревает без автоматизации верно
  • Он занимает много места
  • Требует Linux

Ответ: Быстро устаревает без автоматизации
