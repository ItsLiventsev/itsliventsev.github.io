ALT Workstation и Windows 11 в одном каталоге: доменный вход и единые политики.

О работе

спринт 2 · Учёт · 4 ч · 70 неткоинов

ALT Workstation и Windows 11 в одном каталоге: доменный вход и единые политики.

Бриф практики

лис Итан — да, тот самый из СетьПолиса, теперь на сопровождении · бриф практики

Итан, знакомый по СетьПолису по DHCP и сетям, перешёл в эксплуатацию и теперь вводит рабочие станции в домен. Вы пройдёте его путём: подключите ALT Workstation к Samba AD и Windows 11 к тому же каталогу, проверите единый доменный вход и поймёте, как гетерогенный парк живёт под единой учётной записью.

Теория

опорный конспект

01 Доменный вход на ALT

Рабочая станция настраивается на DNS контроллера, затем входит в домен через Realm/SSSD или инструменты Samba. После входа доменный пользователь получает сессию и home-каталог.

# apt-get install samba-client sssd-ad
# realm discover datapolis.local
# realm join datapolis.local
# getent passwd ivanov@datapolis.local

02 Windows 11 в домене

Клиент указывает DNS контроллера и присоединяется к домену через System Properties или PowerShell. После перезагрузки доступен вход доменной учёткой, политики GPO применяются автоматически.

Add-Computer -DomainName datapolis.local -Restart

03 Проверка единого каталога

Один пользователь логинится и на ALT, и на Windows; группы и политики тянутся из одного источника. Это и есть ценность домена для эксплуатации — учётка выдаётся и отзывается в одном месте.

⚑ Пасхалка: Итан упоминает, что в СетьПолисе адрес этой станции выдавал тот самый DHCP-сервер.

Бэклог задач

чек-лист
  1. Настройте DNS ALT Workstation на контроллер домена и выполните realm discover
  2. Введите ALT-станцию в домен и проверьте getent доменной учётки
  3. Войдите доменным пользователем на ALT и проверьте home-каталог
  4. Введите Windows 11 в тот же домен через Add-Computer и перезагрузите
  5. Войдите той же учёткой на Windows и сопоставьте SID/группы
  6. Проверьте применение базовой политики (блокировка экрана) на обеих ОС
  7. Отработайте откат: выведите станцию из домена и верните обратно

Задача считается выполненной после реальной работы на оборудовании, в эмуляторе или на виртуальной машине. В интерактиве чек-лист сохраняет прогресс.

Проверь себя

контрольный тест
Вопрос 1. Какой DNS должен быть указан у станции перед вводом в домен?
  • Любой публичный
  • DNS контроллера домена верно
  • Провайдерский только
  • DNS не нужен для домена

Ответ: DNS контроллера домена

Клиент находит контроллер через SRV-записи, их отдаёт доменный DNS.

Вопрос 2. Командлет ввода Windows в домен?
  • Join-Domain
  • Add-Computer верно
  • Set-ADClient
  • Enter-Domain

Ответ: Add-Computer

Add-Computer -DomainName ... -Restart выполняет присоединение.

Вопрос 3. Что даёт единый доменный вход на разных ОС?
  • Одинаковые обои
  • Одну учётку, группы и политики для всего парка верно
  • Удаление локальных дисков
  • Только почту

Ответ: Одну учётку, группы и политики для всего парка

В этом смысл каталога: централизованная идентичность в гетерогенной среде.

Вопрос 4. Как откатить неудачный ввод станции?
  • Переустановить ОС
  • realm leave / Remove-Computer и проверить локальный вход верно
  • Сменить MAC-адрес
  • Отключить интернет

Ответ: realm leave / Remove-Computer и проверить локальный вход

Вывод из домена возвращает станцию к локальным учётным записям.
