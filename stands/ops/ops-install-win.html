Бриф практики

Часть сервисов заказчика работает на Windows Server. ДатаПолис поддерживает гетерогенную среду, поэтому дежурный инженер одинаково уверенно принимает и ALT, и Windows. Вы развернёте Windows Server, зададите статический адрес без мастера «по умолчанию», разберётесь в ролях и службах и сравните подход с Linux из предыдущей смены.

Теория

опорный конспект

01 Редакции и роли сервера

Windows Server устанавливается в варианте Desktop Experience или Server Core. Роли (DNS, DHCP, AD DS, файловые службы) добавляются через Server Manager или PowerShell. Минималистичный Server Core потребляет меньше ресурсов и безопаснее за счёт меньшей поверхности атаки.

02 Статический адрес через PowerShell

Автоматизация предпочтительнее кликов: командлеты NetIPInterface и New-NetIPAddress настраивают адрес воспроизводимо, такой скрипт кладётся в runbook.

Get-NetIPInterface -AddressFamily IPv4
New-NetIPAddress -InterfaceAlias "Ethernet" \
  -IPAddress 10.20.30.12 -PrefixLength 24 -DefaultGateway 10.20.30.1
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" \
  -ServerAddresses 10.20.30.11

03 Базовая защита и обновления

После установки проверяют статус Windows Defender Firewall, параметры RDP и план обновлений. Открытым остаётся только то, что нужно сервису — принцип минимальных привилегий действует и в Windows, и в Linux.

Get-NetFirewallProfile
Install-WindowsUpdate -AcceptAll -AutoReboot

Бэклог задач

чек-лист
  1. Установите Windows Server (Desktop Experience или Core) и задайте имя SRV-WIN
  2. Настройте статический IP/PrefixLength/шлюз/DNS через PowerShell, без кликов в ncpa
  3. Проверьте профили брандмауэра и обоснуйте, какие порты нужны для роли
  4. Включите удалённый рабочий стол только для доверенной подсети
  5. Установите обновления и просмотрите системный журнал событий
  6. Сравните чек-листы приёмки ALT и Windows: выпишите совпадающие пункты
  7. Перезагрузите и подтвердите сохранение всех настроек

Задача считается выполненной после реальной работы на оборудовании, в эмуляторе или на виртуальной машине. В интерактиве чек-лист сохраняет прогресс.

Подготовить Windows Server к роли приложений

тип: request · приоритет: P3

Заказчику нужен Windows Server для будущего веб-приложения. Разверните ОС, настройте статическую адресацию и удалённый доступ, подготовьте сервер к добавлению ролей. Приёмка — по чек-листу, идентичному по смыслу Linux-приёмке.

Проверь себя

контрольный тест
Вопрос 1. Чем Server Core отличается от Desktop Experience?
  • Не поддерживает сеть
  • Меньше компонентов и поверхности атаки верно
  • Это клиентская Windows 11
  • Не умеет обновляться

Ответ: Меньше компонентов и поверхности атаки

Core — без графической оболочки, легче и безопаснее, управляется PowerShell/WinRM.

Вопрос 2. Какой командлет задаёт статический IP?
  • Set-IP
  • New-NetIPAddress верно
  • ipconfig /set
  • Add-Address

Ответ: New-NetIPAddress

New-NetIPAddress с параметрами InterfaceAlias, IPAddress, PrefixLength, DefaultGateway.

Вопрос 3. Где в Windows смотреть системные события загрузки?
  • Диспетчер устройств
  • Журнал событий / Get-EventLog верно
  • Панель управления темами
  • Корзина

Ответ: Журнал событий / Get-EventLog

Event Log (System) — аналог journalctl в Linux.

Вопрос 4. Что общего у приёмки ALT и Windows Server?
  • Ничего
  • Имя, статический адрес, обновления, проверка служб, чек-лист верно
  • Только перезагрузка
  • Обе требуют графику

Ответ: Имя, статический адрес, обновления, проверка служб, чек-лист

Сервисные практики платформонезависимы, различаются инструменты.
