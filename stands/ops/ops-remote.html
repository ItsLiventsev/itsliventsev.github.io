Бриф практики

Дежурства требуют удалённого доступа к серверам, но открытый наружу SSH с паролем root — приглашение для ботов. Вы усилите SSH на ALT (ключи, запрет root, нестандартный порт, баннер), поставите fail2ban против перебора и параллельно настроите безопасный RDP на Windows. В конце — изменение с коротким планом отката, чтобы не заблокировать собственный доступ.

Теория

опорный конспект

01 Усиление SSH

Переход на ключи, запрет пароля и входа root, ограничение пользователей и смена порта снижают поверхность атаки. Правило дежурного: не закрывать текущую сессию, пока не проверен новый вход.

# apt-get install openssh-server
# mcedit /etc/openssh/sshd_config
PermitRootLogin no
PasswordAuthentication no
AllowUsers noc eng
Port 2027
# systemctl restart sshd

02 fail2ban против брутфорса

Демон анализирует журнал неудачных входов и временно блокирует IP по правилу jail. Это автоматический ответ на перебор, не требующий ручного дежурства.

# apt-get install fail2ban
# mcedit /etc/fail2ban/jail.d/sshd.conf
[sshd]
enabled = true
maxretry = 4
bantime = 1h
# systemctl restart fail2ban ; fail2ban-client status sshd

03 RDP и его защита

В Windows удалённый рабочий стол включают только для нужных пользователей и подсети, включают NLA, ограничивают брандмауэром. Полный доступ наружу без шлюза/VPN — недопустим.

Set-ItemProperty "HKLM:\System\CurrentControlSet\Control\Terminal Server" fDenyTSConnections 0
Enable-NetFirewallRule -DisplayGroup "Remote Desktop"

Бэклог задач

чек-лист
  1. Настройте вход по ключу и отключите парольную аутентификацию на ALT
  2. Запретите вход root, ограничьте AllowUsers и добавьте баннер доступа
  3. Перенесите SSH на нестандартный порт, не потеряв текущую сессию
  4. Установите fail2ban, воспроизведите перебор и покажите заблокированный IP
  5. На Windows включите RDP с NLA для группы администраторов и ограничьте фаерволом
  6. Составьте план отката на случай блокировки собственного доступа
  7. Проведите изменение и оформите runbook безопасного доступа

Задача считается выполненной после реальной работы на оборудовании, в эмуляторе или на виртуальной машине. В интерактиве чек-лист сохраняет прогресс.

Проверь себя

контрольный тест
Вопрос 1. Почему нельзя закрывать текущую SSH-сессию при смене настроек?
  • Это правило этикета
  • Ошибка в конфиге может навсегда закрыть доступ верно
  • SSH не позволяет редактировать
  • Сессия влияет на fail2ban

Ответ: Ошибка в конфиге может навсегда закрыть доступ

Пока старая сессия жива, есть способ исправить конфигурацию.

Вопрос 2. Что делает fail2ban?
  • Шифрует диск
  • Блокирует IP после серии неудачных входов верно
  • Удаляет пользователей
  • Меняет порт автоматически

Ответ: Блокирует IP после серии неудачных входов

Анализ журнала + бан по правилу jail — автоматическая защита от брутфорса.

Вопрос 3. Какой механизм Windows обязателен для безопасного RDP?
  • Отключить фаервол
  • NLA — проверка подлинности до сессии верно
  • Использовать порт 80
  • Включить гостевой вход

Ответ: NLA — проверка подлинности до сессии

Network Level Authentication снижает поверхность атаки до логина.

Вопрос 4. Что надёжнее пароля для SSH?
  • Короткий PIN
  • Ключевая пара Ed25519/RSA верно
  • Пароль на стикере
  • Один пароль на всех

Ответ: Ключевая пара Ed25519/RSA

Криптоключи не передаются по сети и не подбираются простым перебором.
