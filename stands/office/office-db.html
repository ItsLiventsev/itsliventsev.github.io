Учебная часть вела записи в одной гигантской таблице: один студент дублировался в шести строках, а опечатка в названии группы ломала фильтры. Тихон разбирает базу по нормальным таблицам со связями «один ко многим», формы для ввода и запросы, которые отвечают на вопросы без ручного перебора.

Теория

опорный конспект

01 Таблицы, ключи и нормализация

Каждая сущность — своя таблица: студенты, группы, работы. Первичный ключ однозначно задаёт запись, внешний ключ ссылается на неё из другой таблицы. Первая нормальная форма убирает списки в ячейке, вторая убирает повторяющиеся факты — дубликаты исчезают.

-- пример связи и запроса
CREATE TABLE groups (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL
);
-- students.group_id -> groups.id

02 Формы и проверка ввода

Форма — дружелюбный ввод данных вместо голой таблицы: выпадающие списки, обязательные поля, маски. Ограничения на уровне таблицы не пускают NULL в ключевое поле и неверные форматы даты.

⚑ Целостность данных защищают на входе: исправлять опечатки в тысяче строк в разы дороже.

03 Запросы и отчёты

QBE-конструктор собирает запрос кликами, SQL — тот же запрос текстом: SELECT с JOIN связывает таблицы, WHERE фильтрует, GROUP BY считает итоги. Отчёт форматирует выдачу для печати с группировкой и итогами.

SELECT g.name, COUNT(s.id) AS students
FROM groups g
LEFT JOIN students s ON s.group_id = g.id
GROUP BY g.name
ORDER BY students DESC;

Бэклог задач

чек-лист
  1. Спроектируйте 3–4 таблицы (студенты, группы, работы, оценки) с первичными ключами
  2. Постройте связи один-ко-многим и включите целостность данных
  3. Заполните 15–20 записей через форму со списками и обязательными полями
  4. Соберите QBE-запрос: фильтр по группе и сортировка по дате
  5. Напишите SQL с JOIN и GROUP BY: число студентов по группам
  6. Сформируйте отчёт с группировкой и итогами, экспортируйте в PDF

Задача считается выполненной после реальной работы на оборудовании, в эмуляторе или на виртуальной машине. В интерактиве чек-лист сохраняет прогресс.

Проверь себя

контрольный тест
Вопрос 1. Зачем данные раскладывают по разным таблицам со связями?
  • Чтобы было сложнее
  • Убрать дубли и обеспечить целостность верно
  • Чтобы замедлить запросы
  • Это устаревший приём

Ответ: Убрать дубли и обеспечить целостность

Нормализация устраняет повторяющиеся факты: правка названия группы происходит в одной записи.

Вопрос 2. Что такое внешний ключ?
  • Пароль к базе
  • Поле, ссылающееся на первичный ключ другой таблицы верно
  • Резервная копия
  • Тип шрифта

Ответ: Поле, ссылающееся на первичный ключ другой таблицы

Внешний ключ строит связь один-ко-многим и не даёт ссылаться на несуществующую запись.

Вопрос 3. Форма в базе данных нужна, чтобы…
  • Украсить таблицу
  • Вводить данные контролируемо: списки, маски, обязательные поля верно
  • Удалить связи
  • Заменить запросы

Ответ: Вводить данные контролируемо: списки, маски, обязательные поля

Форма ловит ошибки на входе и делает ввод доступным неподготовленному пользователю.

Вопрос 4. Что делает SQL-конструкция GROUP BY?
  • Удаляет группы
  • Сворачивает строки в группы и считает по ним итоги верно
  • Группирует окна приложения
  • Сортирует по алфавиту только

Ответ: Сворачивает строки в группы и считает по ним итоги

GROUP BY в паре с COUNT/SUM даёт сводки, например число студентов в каждой группе.
