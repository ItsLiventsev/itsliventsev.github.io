VLAN и 802.1Q: один провод, много сетей

VLAN отделяет сегмент на уровне кадра, а не кабеля; тег 802.1Q — это 4 байта, из которых 12 бит отведены под номер сети, поэтому в одном домене можно держать 4094 VLAN.

Кадр Ethernet не знает, к какой «сети» он относится. Он просто идёт от MAC к MAC, и коммутатор рассылает его всем портам одного широковещательного домена. VLAN добавляет в кадр четыре байта, которые говорят коммутатору: этот кадр принадлежит сети с номером N. Всё остальное — следствия.

Четыре байта и что в них лежит

Тег вставляется после MAC-адреса источника, перед полем EtherType. Внутри — TPID (0x8100), три бита приоритета PCP, бит DEI и 12 бит VID.

TPID
0x8100 — признак того, что дальше идёт тег 802.1Q
PCP
3 бита приоритета (802.1p), 0 — обычный трафик, 7 — самый высокий
DEI
1 бит: кадр можно сбросить первым при перегрузке
VID
12 бит, рабочий диапазон 1–4094; 0 и 4095 зарезервированы

12 бит дают 4096 значений, но 0 и 4095 зарезервированы: 0 означает «приоритетный тег без VLAN», 4095 стандарт не использует. Рабочих номеров — 4094. Если этого мало, второй тег (QinQ, 802.1ad, TPID 0x88a8) добавляет ещё один уровень, но вместе с ним растёт кадр и усложняется диагностика.

Есть и побочный эффект: кадр становится на 4 байта длиннее. Обычный максимум 1518 байт превращается в 1522. Для большинства коммутаторов это норма, но старые устройства и некоторые виртуальные драйверы такие кадры дропают. Если после включения тега «пропал» только крупный трафик, а ping идёт — это оно.

Access и trunk: кто ставит тег

voiceтелефон + ПКдва теганеправильный PCP у голоса
Access и trunk решают разные задачи; ошибка почти всегда в несогласованном native VLAN.

Порт access — это порт одного VLAN. Кадр приходит от компьютера без тега, коммутатор сам относит его к VLAN порта, а на trunk-порту ставит тег. Порт trunk несёт сразу несколько VLAN, и каждый кадр помечен, кроме одного — native VLAN, который идёт без тега «для совместимости».

Native VLAN — главный источник тихих аварий. Если на одном конце trunk native VLAN 1, а на другом 99, то нетегированные кадры попадают в разные сети, и связь «есть, но не туда». Вторая проблема — безопасность: кадр без тега при выходе на другой конец получает тег native VLAN, поэтому атакующий, отправив кадр с двумя тегами (double tagging), может дотянуться до сети, к которой не подключён. Защита простая: выделить под native VLAN отдельный номер, которого нет ни на одном access-порту, и запретить его в разрешённом списке.

Как это выглядит в Linux

На сервере VLAN — это обычный интерфейс поверх физического:

ip link add link eth0 name eth0.20 type vlan id 20
ip link set eth0.20 up
ip -d link show eth0.20      # покажет id и flags
bridge vlan show             # какие VLAN пропущены через мост

Виртуальный коммутатор (Open vSwitch, linux bridge) настраивается тегами на портах: access — один тег снимается, trunk — список разрешённых, native — тег по умолчанию. Ошибка «забыли добавить VLAN в список разрешённых» даёт ровно один симптом: в этой сети не отвечает даже шлюз, хотя соседние работают.

Практические правила

  1. Номер — не смысл. Значение VID ничего не говорит о назначении сети; смысл живёт в документации и в имени интерфейса (eth0.20).
  2. Один VLAN — один широковещательный домен. Не «оптимизируйте» делением на 60 VLAN по одному хосту, если нет политики: таблицы MAC и STP этого не любят.
  3. Management VLAN отдельно. Портал управления коммутатором не должен быть доступен из студенческой сети.
  4. MTU помнить. Для QinQ и VXLAN кадр растёт сильнее, чем на 4 байта; проверку MTU см. в заметке про размер пакета.

Дальше логичный вопрос — что происходит, когда кадр покидает свой VLAN: решение принимает маршрутизатор, и об этом таблица маршрутов. А если адреса в новом VLAN раздаются автоматически, пригодится разбор DORA.
