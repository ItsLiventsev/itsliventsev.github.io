Анализ трафика: что показывает сниффер

Анализатор трафика отвечает на вопросы, которые не решаются конфигурацией: идут ли пакеты, в каком порядке, с какими флагами и кто их отбрасывает.

Что вы будете уметь

  • снимать трафик с нужного интерфейса, не записывая лишнего;
  • читать установление TCP-соединения по флагам;
  • по одной сессии отличать «пакет не дошёл» от «ответ не пришёл».

Машинная обработка. Текст структурирован и собран с помощью ИИ на основе материалов автора: структура и формулировки — ассистента, содержание и терминология — авторские. Проверяйте команды и значения на своём стенде.

Зачем снимать трафик

Конфигурация показывает, что должно происходить. Сниффер — что происходит. Разница обнаруживается в трёх типичных случаях:

  • пакеты уходят, но ответа нет (фильтр, маршрут, адрес назначения);
  • соединение устанавливается, но данные не идут (MTU, TLS, приложение);
  • трафик есть, но не тот (петля, широковещание, чужое устройство).

Снятие и чтение

tcpdump -ni any host 192.168.10.20 and port 443
tcpdump -ni eth0 'tcp[tcpflags] & (tcp-syn|tcp-fin) != 0'
tcpdump -ni any -w /tmp/cap.pcap port 80
tcpdump -r /tmp/cap.pcap -nn | head -50

Ключи, которые экономят время:

  • -n — не разрешать имена (быстрее и без лишних DNS-запросов);
  • -i any — все интерфейсы сразу, удобно на сервере с несколькими сетями;
  • -s 0 — писать пакет целиком, а не первые байты;
  • -w — писать в файл, чтобы читать в Wireshark;
  • фильтр в кавычках — синтаксис pcap, а не shell.

Как читать TCP по флагам

Три пакета установления соединения выглядят так:

client > server: Flags [S]   seq 0
server > client: Flags [S.]  seq 0 ack 1
client > server: Flags [.]   ack 1

Дальше полезно смотреть на четыре признака:

ПризнакЧто значит
[S] без ответапакет не дошёл или его отбросили
[S] → [R]порт закрыт или запрещён политикой
[S] повторяетсяфильтр молча дропает, ответ не возвращается
[.] с нулевым окномполучатель просит подождать, приложение не читает
[P.] с большим seq и без ackданные уходят, подтверждений нет

Отличие [R] от молчания принципиально: отказ (reset) означает, что до хоста дошли и его отклонили; тишина — что до хоста не дошли, или ответ не вернулся.

Фильтры, которые пригодятся

# только установление соединения
tcpdump -ni eth0 'tcp[tcpflags] & tcp-syn != 0 and tcp[tcpflags] & tcp-ack == 0'
# DNS-запросы и ответы
tcpdump -ni any port 53
# DHCP-диалог
tcpdump -ni eth0 port 67 or port 68
# ICMP, включая «fragmentation needed»
tcpdump -ni any icmp and icmp[icmptype] == 3

Последний фильтр — прямой путь к разгадке «ping идёт, а сайт нет»: сообщение ICMP type 3 code 4 (fragmentation needed) показывает, кто и где требует уменьшить размер пакета.

Wireshark: что смотреть в первую очередь

  • Statistics → Conversations — кто с кем и сколько. Сразу видно «кто занял канал».
  • Follow → TCP Stream — содержимое сессии в читаемом виде.
  • Expert Information — автоматические замечания: повторные передачи, сбросы, ошибки контрольных сумм.

Для быстрой оценки «сеть тормозит» достаточно первых двух: разговор на гигабайт от одного адреса виден сразу.

Правила приличия и безопасности

  • Снимать только свою сеть и только по задаче; в учебном стенде — только трафик стенда.
  • Не сохранять персональные данные в дампах; если сняли — удалять после разбора.
  • Не запускать захват «на всякий случай» на весь день: файл растёт гигабайтами.
  • На управляемых коммутаторах порт-зеркало настраивается явно, «само» трафик не появится.

Итог

  • Сниффер показывает факты, конфигурация — намерения; полезно и то, и другое.
  • -n -i any и pcap-фильтр — минимальный набор для работы.
  • [R] — дошло и отклонили; тишина — не дошло.
  • ICMP type 3 code 4 объясняет большинство «странных» зависаний.

Подробности по пакетам — tcpdump: как читать пакет, а не гадать, про MTU — MTU и PMTU: ping идёт, скачивание нет.
