IP-адресация: адрес, маска, шлюз

IP-адрес без маски бессмысленен: маска отделяет адрес сети от адреса узла, а шлюз — единственный способ выйти за пределы своего сегмента.

Что вы будете уметь

  • читать адрес вместе с маской и называть адрес сети и широковещательный;
  • объяснять роль шлюза и почему без него нет выхода наружу;
  • выбирать диапазоны для офиса, гостей и оборудования.

Из чего состоит адрес

IPv4-адрес — 32 бита, записанные четырьмя числами: 192.168.10.25. Он ничего не значит без маски: 255.255.255.0 (или /24) говорит, что первые 24 бита — это номер сети, а последние 8 — номер узла.

Отсюда всё остальное:

  • Адрес сети — все биты узла в нуле: 192.168.10.0. Узлу его назначать нельзя.
  • Широковещательный адрес — все биты узла в единице: 192.168.10.255. Тоже не назначается.
  • Диапазон узлов — между ними: 192.168.10.1 … 192.168.10.254, то есть 254 адреса в /24.

Два адреса в каждой подсети заняты служебно, поэтому «/24 = 256 адресов для устройств» — ошибка планирования, которая всплывает, когда подсеть заполнена ровно.

Классы и частные диапазоны

Исторические классы A/B/C давно заменены бесклассовой схемой (CIDR), но частные диапазоны остаются неизменными по RFC 1918:

ДиапазонМаскаРазмерГде уместен
10.0.0.0/8/816,7 млнкрупная организация
172.16.0.0/12/121 млнсредняя сеть, кампус
192.168.0.0/16/1665 тысофис, дом, филиал
169.254.0.0/16/16—self-assigned, признак проблемы с DHCP

Диапазон 169.254.x.x (APIPA) — важный диагностический признак: если компьютер получил такой адрес, значит DHCP-сервер недоступен. Это первое, что стоит проверить, когда «сеть есть, но интернета нет».

Шлюз по умолчанию

Шлюз — адрес маршрутизатора в той же подсети. Логика проста: если адрес назначения попадает в «свою» подсеть, узел отправляет кадр напрямую по MAC-адресу; если нет — отдаёт кадр шлюзу и просит его разобраться.

Из этого следуют две частые ошибки:

  • Шлюз из другой подсети. Формально настраивается, фактически не работает: узел не может отправить кадр шлюзу, потому что тот за пределами локального сегмента.
  • Нет шлюза. Всё внутри работает, всё снаружи — нет. Симптом ровно такой: пинги по локальным адресам идут, интернет молчит.

Служебные и гостевые диапазоны

В плане адресации полезно держать разделение по назначению, а не по «где свободно»:

НазначениеПримерПочему отдельно
Управление оборудованием192.168.250.0/24доступ только администраторам
Серверы192.168.20.0/24фиксированные адреса, резерв под рост
Рабочие места192.168.10.0/23DHCP, запас на 500 мест
Гости192.168.99.0/24изоляция и лимиты
Точка-точка10.255.0.0/30 или /31без широковещательного адреса

Для линков между маршрутизаторами по RFC 3021 используют /31: два адреса, ни одного занятого служебно. Это экономит адреса на магистралях с десятками сессий.

Проверка на месте

ip address show            # адрес и маска
ip route                   # шлюз по умолчанию и маршруты
ip neigh                   # какие MAC выучены в сегменте
ping -c 3 <шлюз>           # доступен ли шлюз
traceroute 8.8.8.8         # где обрывается путь

Порядок проверки важен: сначала адрес и маска, потом шлюз, потом маршрут. Если адрес получен от DHCP не из той подсети, остальное диагностировать бессмысленно.

Итог

  • Адрес имеет смысл только с маской: она отделяет сеть от узла.
  • В каждой подсети два адреса заняты — сетевой и широковещательный.
  • Без шлюза узел не выходит за пределы сегмента; шлюз обязан быть в той же подсети.
  • 169.254.x.x — сигнал, что DHCP недоступен.
