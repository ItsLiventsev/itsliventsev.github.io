DHCP: как устройство получает адрес

Аренда адреса — это четыре сообщения и набор таймеров; понимание процесса объясняет, почему компьютер остался без сети и почему в подсети кончились адреса.

Что вы будете уметь

  • описывать четыре шага аренды и роль широковещания;
  • настраивать область и исключения без ошибок планирования;
  • находить причину «адрес 169.254» за одну проверку.

Машинная обработка. Текст структурирован и собран с помощью ИИ на основе материалов автора: структура и формулировки — ассистента, содержание и терминология — авторские. Проверяйте команды и значения на своём стенде.

Четыре шага

Устройство без адреса не знает, где сервер DHCP, поэтому первый шаг — широковещательный.

  1. Discover — клиент отправляет broadcast: «есть ли здесь DHCP-сервер?».
  2. Offer — сервер отвечает предложением: адрес, маска, шлюз, DNS, срок аренды.
  3. Request — клиент просит именно этот адрес (широковещательно, чтобы о решении узнали все серверы).
  4. ACK — сервер подтверждает, и клиент применяет настройки.

Все четыре сообщения — UDP: клиент с порта 68, сервер на порт 67. Широковещательность шага 1 и 3 объясняет, почему DHCP-сервер должен быть в том же сегменте или за relay-агентом.

Реле между VLAN

Сервер DHCP обычно один на организацию, а подсетей много. Чтобы запрос из VLAN 20 дошёл до сервера в VLAN 10, на маршрутизаторе настраивают relay (DHCP helper):

interface gi0/0.20
 ip helper-address 192.168.10.5

Маршрутизатор получает broadcast, превращает его в unicast к указанному серверу и запоминает, из какой подсети пришёл запрос. Сервер выбирает область по адресу шлюза (giaddr), а не по адресу клиента — клиент своего адреса ещё не имеет.

Если relay не настроен, устройство в новом VLAN не получит адрес никогда, хотя в соседнем VLAN всё работает. Это одна из самых частых ошибок при добавлении подсети.

Таймеры аренды

ТаймерЗначение по умолчаниюЧто происходит
T1 (renew)50 % срока арендыклиент просит продлить у того же сервера
T2 (rebind)87,5 % срока арендыклиент рассылает запрос всем серверам
Истечение100 %адрес освобождается, устройство теряет сеть

При аренде на 8 часов продление начнётся через 4 часа, а в 7 часов клиент начнёт искать любой сервер. Пока устройство выключено, адрес не продлевается — именно поэтому после долгого простоя машина может получить другой адрес.

Настройка области

ip dhcp pool office
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1
 dns-server 192.168.10.10 192.168.10.11
 lease 0 8
 domain-name example.local
ip dhcp excluded-address 192.168.10.1 192.168.10.20

Две строки критичны:

  • excluded-address — диапазон, который сервер не выдаёт. Туда входят шлюз, серверы, принтеры, камеры и оборудование с фиксированными адресами.
  • lease — срок аренды. Слишком короткий создаёт лишний трафик, слишком длинный мешает переиспользовать адреса в гостевой сети.

В Linux сервер настраивается через dnsmasq или isc-dhcp-server:

# dnsmasq
dhcp-range=192.168.10.50,192.168.10.200,12h
dhcp-option=3,192.168.10.1
dhcp-option=6,192.168.10.10

Диагностика

СимптомПричина
адрес 169.254.x.xсервер недоступен или не отвечает
адрес из чужой подсетив сегменте второй DHCP-сервер
адрес есть, интернета нетневерный шлюз или DNS в опции
«кончились адреса»пул меньше числа устройств или много долгих аренд

Команды:

ip address show                 # какой адрес фактически
sudo dhclient -v eth0           # запрос с раскрытием диалога
journalctl -u dhcpd -n 50       # что видел сервер
sudo tcpdump -ni eth0 port 67 or port 68   # полный диалог

169.254.x.x (APIPA) — самый быстрый сигнал: адрес не получен, сервер не ответил. Дальше вопрос один: сервер, релей или VLAN.

Итог

  • Аренда — четыре сообщения: Discover, Offer, Request, ACK.
  • Relay нужен, если сервер в другом сегменте.
  • Таймеры T1/T2 управляют продлением; выключенное устройство не продлевает адрес.
  • Исключить из пула оборудование с фиксированными адресами — обязательно.
