Коммутация: как коммутатор находит получателя

Коммутатор учит MAC-адреса по источнику кадра и передаёт его только в нужный порт; понимание этой механики объясняет и «сеть тормозит», и «порт заблокирован», и «петля положила офис».

Что вы будете уметь

  • объяснять, как таблица MAC заполняется и почему она стареет;
  • отличать unknown unicast, broadcast и flooding;
  • находить причину петли и понимать, зачем нужен STP.

Машинная обработка. Текст структурирован и собран с помощью ИИ на основе материалов автора: структура и формулировки — ассистента, содержание и терминология — авторские. Проверяйте команды и значения на своём стенде.

Таблица, из которой всё следует

Коммутатор — это мост, который ведёт таблицу соответствия «MAC-адрес → порт». Заполняется она сама, обучением по источнику:

  1. Приходит кадр на порт 7.
  2. Коммутатор смотрит на MAC источника aa:bb:cc:00:11:22 и записывает: этот адрес живёт за портом 7.
  3. Смотрит на MAC назначения. Если он есть в таблице — передаёт кадр только в нужный порт.
  4. Если адреса нет — рассылает кадр во все порты, кроме входного (flooding), и ждёт ответа, чтобы выучить адрес.

Записи стареют, обычно за 300 секунд: устройство, которое молчит, удаляется из таблицы. Это нормально — иначе таблица распухла бы после каждой смены оборудования.

Три типа трафика

ТипMAC назначенияЧто делает коммутатор
Unicast известныйконкретный, есть в таблицепередаёт в один порт
Unicast неизвестныйконкретный, нет в таблицерассылает во все порты (flooding)
Broadcastff:ff:ff:ff:ff:ffрассылает во все порты домена
Multicastгрупповойпередаёт по правилам IGMP snooping

Из этой таблицы видно, почему широковещательный домен — ограничение: каждый broadcast будит все устройства сегмента, и на большом домене это превращается в фоновую нагрузку. Ограничивают его VLAN — тема VLAN и транки: один кабель, много сетей.

Что видно в реальной сети

Петля. Если соединить два коммутатора двумя кабелями, broadcast начнёт ходить по кругу, таблица MAC будет постоянно переучиваться («flapping»), полоса заполнится за секунды, и сеть ляжет целиком. Именно от этого защищает STP — STP: почему порт сам выключился. Признак петли в логах: MAC-адрес одного устройства появляется то на одном порту, то на другом.

Медленный сегмент. Один полудуплексный линк или устройство, которое генерирует broadcast, снижает скорость всего домена. Смотреть счётчики: ip -s link, на коммутаторе — show interfaces counters errors.

Порт в состоянии err-disabled. Коммутатор сам выключил порт: петля, лимит MAC, конфликт адреса. Лечится не перезагрузкой, а пониманием причины — на коммутаторах это видно в show interfaces status err-disabled.

Настройки, которые действительно нужны

  • Port security — ограничение числа MAC на порту: одно рабочее место — один-два адреса. Не даёт подключить «самодельный» коммутатор в кабинет.
  • Storm control — лимит на broadcast/multicast в процентах полосы: спасает сеть от лавины, а не отказывает целиком.
  • BPDU guard — порт, на котором не должно быть STP-кадров (порты доступа), при их появлении отключается. Останавливает самый частый способ устроить петлю.
  • Описание порта — «каб. 302, рабочее место 5»: через месяц это экономит полчаса.

Проверка после настройки

show mac address-table            — выучился ли адрес нужного устройства
show mac address-table address X  — на каком порту живёт конкретный MAC
show interfaces status            — скорости и состояния портов
show spanning-tree                — кто корень, какие порты заблокированы

На Linux мост настраивается через bridge или ip link:

ip link add br0 type bridge
ip link set eth1 master br0
ip link set eth2 master br0
ip link set br0 up
bridge link show

Именно так устроен Open vSwitch, который встречается в учебных стендах и в серверных виртуализациях.

Итог

  • Коммутатор учится по источнику и передаёт по назначению; неизвестный адрес — flooding.
  • Broadcast ограничен доменом, и его размер — главная причина «сеть тормозит».
  • Петля убивает домен за секунды; защита — STP, BPDU guard и дисциплина монтажа.
  • Полезные настройки порта: port security, storm control, описание.

  • VLAN и 802.1Q: один провод, много сетейРазбор тега 802.1Q по полям, access и trunk, native VLAN и почему двойной тег уводит кадр в чужую сеть при агрегации каналов.
  • STP: почему коммутатор сам выключил портКорневой мост по наименьшему идентификатору, роли и состояния портов, RSTP вместо ожидания по 30 секунд и три защиты, без которых STP опасен.
  • LACP: два кабеля, один адресactive и passive, зачем нужен LACPDU, почему скорость одного потока не растёт, откуда взялся cut-through и как не получить петлю из двух кабелей.
