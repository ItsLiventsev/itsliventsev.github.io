Расчёт подсетей без калькулятора

Деление на подсети — это арифметика степеней двойки; один раз поняв связь маски с количеством адресов, вы перестанете ошибаться в планировании.

Что вы будете уметь

  • считать количество адресов по префиксу и наоборот;
  • делить сеть на подсети заданного размера без ошибок;
  • выбирать размер подсети с запасом, а не «впритык».

Правило одно: количество адресов равно 2 в степени (32 − префикс), для узлов вычитаем два — сетевой и широковещательный. Исключение — /31: два адреса, оба пригодны для узлов на point-to-point линках.

Деление на подсети

Задача: сеть 192.168.10.0/24 нужно разделить на четыре подсети.

Шаг 1. Сколько бит добавить? Четыре подсети — это 2², значит два бита. Префикс становится /26. Шаг 2. Каков размер каждой? 2^(32−26) = 64 адреса. Шаг 3. Выписать диапазоны с шагом 64:

ПодсетьДиапазон узловШироковещательный
192.168.10.0/26.1 – .62.63
192.168.10.64/26.65 – .126.127
192.168.10.128/26.129 – .190.191
192.168.10.192/26.193 – .254.255

Проверка: 4 × 62 = 248 пригодных адреса из 254 исходных — разница ушла на служебные адреса четырёх подсетей вместо двух. Каждое деление «съедает» по два адреса, и это нормально.

Неравные подсети (VLSM)

Когда отделы разного размера, делить на равные — расточительство. VLSM позволяет нарезать по потребности: сначала самая большая подсеть, потом следующая по размеру.

Пример для 10.20.0.0/22 (1024 адреса):

  1. Серверы, 200 адресов → ближайшая степень двойки 256 → /24 = 10.20.0.0/24
  2. Рабочие места, 500 адресов → 512 → /23 = 10.20.2.0/23
  3. Гости, 100 адресов → 128 → /25 = 10.20.4.0/25
  4. Транзит, 2 адреса → /30 = 10.20.4.4/30

Итого занято 256 + 512 + 128 + 4 = 900 из 1024, свободно 124 адреса под рост. Если бы делили на четыре равные /24, не хватило бы уже на втором шаге.

Запас, который надо закладывать

Планировщики сетей сходятся в одном правиле: подсеть не должна заполняться более чем на 60–70 %. Причины простые:

  • DHCP-пул должен иметь свободные адреса для новых устройств.
  • Служебные адреса (принтеры, камеры, контроллеры) часто выдают статически «поверх» DHCP.
  • Гости приходят волной, а резервировать адреса заранее дешевле, чем перенастраивать подсеть.

Поэтому «нужно 50 мест — беру /26 на 62» — плохой расчёт: через месяц будет 70 устройств. Нужно 50 — берётся /25 на 126.

Быстрая проверка на месте

# какой адрес сети у конкретного IP
ipcalc 192.168.10.130/26
# или без ipcalc — арифметикой в shell
ip -4 addr show eth0
ip route get 192.168.10.100

В ipcalc смотрите три строки: Network, Broadcast и HostMin/HostMax. Если HostMin/HostMax не совпадают с вашим планом, ошибка в префиксе, а не в «глючном DHCP».

Итог

  • Адресов в подсети — 2^(32−префикс), для узлов на два меньше.
  • Деление: прибавляем биты под подсети, шаг считаем как размер новой подсети.
  • VLSM: сначала крупные подсети, потом мелкие.
  • Закладывать запас: заполнение выше 70 % — повод для следующей подсети.

Планирование диапазонов — IP-адресация: адрес, маска, шлюз, порядок в таблице адресов — План адресации: сеть начинается с таблицы.
